# 单机 PPO 随机风况使用指南

> 2026-09-13；环境版本 `stochastic_single_v2`，风况版本 `kaimal_single_point_v1`。
> 已实现环境、训练入口、文件回放、统计图与测试。短训练权重只验证流程，不证明控制性能。

## 1. 这次增加了什么

`wind_generator.py` 将风速分解成背景平均风、Kaimal 湍流和事件；`stochastic_turbine_env.py` 把它接入独立的 v2 单机环境；`train.py --wind-config` 选择新环境；`wind_workflow.py` 导出场景、检查统计并回放 P 基准和可选 PPO。

旧 `SimplifiedTurbineEnv`、旧五维模型和 `eval.py --policy-format legacy_unsquashed` 保持原用途。新版八维模型必须使用本指南的回放入口，不能交给旧 `eval.py`。

## 2. 风从哪里来

方法依据是 [TurbSim v2 用户指南，Kaimal 谱 Eq. 23](https://openfast.readthedocs.io/en/main/_downloads/cb14d3e2d3533d76e405d730fea19846/TurbSim_v2.00.pdf)：

`S(f) = 4 sigma² L / U / (1 + 6 f L / U)^(5/3)`，`sigma = TI * U`。

采用随机高斯 Fourier 系数和逆 FFT；正确处理单边谱系数、DC 与 Nyquist，生成长度为回合约 8 倍的序列，再截取一段，避免回合首尾被强制周期连接。不逐回合强制减均值或缩放标准差，因此每条记录的实际 TI 会自然变化。验证采用多条独立记录的平均频谱和均方值。

1 秒采样的 Nyquist 频率为 0.5 Hz；高于它的能量被舍弃，既不混叠到低频，也不人为补回。配置中的 TI 是目标背景谱的全频标准差/平均风速，实际有限带宽和有限长度的 TI 不要求严格等于输入值。功率谱验证避开最低频点与 Nyquist 邻域，统计 0.03–0.35 Hz 内集合平均 PSD/理论 PSD 的中位数；均方值比值使用离散谱积分，保留有限截段的均值偏移。

默认参数来自训练设计，**没有拟合某个真实风场**：

| 参数 | 默认值 | 解释 |
|---|---|---|
| 时间步 / 回合 | 1 s / 600 s | 共 600 次动作，轨迹有 601 个时间点 |
| 回合平均风速 | 6–10 m/s | 四个分层，回合和 worker 循环覆盖 |
| 背景 TI | 0.06 / 0.08 / 0.10 | 每回合抽取 |
| 纵向长度尺度 L | 100 m | 独立设计假设，非指定站点/IEC 机型参数 |
| 慢变化 | ±1 m/s | 回合 20%–80% 区间用 smoothstep 平滑过渡 |
| 阵风 | +1.5 m/s，40 s | 随机开始时间，余弦脉冲；非 IEC 极端阵风 |
| 工作风速包络 | 0.5–16 m/s | 数值训练包络，不是代理有效域或真实切入/切出曲线 |
| 混合场景 | stationary / ramp / gust | 每回合等概率抽取，不代表真实天气频率 |

风速 = 背景 + 湍流 + 事件。慢变化时湍流仍用回合初始平均风标定，即平稳残差叠加慢趋势的简化方法。第一版固定风向，不包含偏航、三维空间相干性、叶轮空间平均、载荷或尾流传播。

越包络时保持已抽取的背景/事件参数，重新生成湍流，记录 `rejected_attempts`；超过上限报错，不裁剪序列。拒绝采样会使分布成为条件分布，窄包络配置须特别检查拒绝次数。不能把 0.5–16 m/s 包络直接作为 FLORIS 代理模型的可用范围。

## 3. 随机性和回放

主种子 42。`SeedSequence([seed, split_id, worker, episode])` 派生子流：train=0、validation=1、test=2。同配置和标识生成同样的风；`reset()` 自动推进 episode；`reset(seed=42)` 明确从该种子的第 0 回合重新开始。

CSV 列为 `time_s,speed_m_s,background_m_s,turbulence_m_s,event_m_s`。同名 JSON 记录参数、场景、种子、实际抽样均值、TI、拒绝次数和 SHA-256。导入必须同时有 CSV 和 JSON，校验失败拒绝回放。已有输出目录、轨迹和模型不覆盖，重复运行使用新目录名称。

轨迹可以提前生成，但环境只返回当前观测；未来轨迹和生成器隐藏变量不传给策略。相关风本身仍可能构成部分可观测过程，八维观测并不宣称重建完整气象 Markov 状态。

## 4. 新环境的物理与时间语义

沿用经验 Cp 功率模型、NREL 5MW 的部分尺度参数，并非完整的 NREL 气动弹性模型。转速为一阶参考跟踪，采用精确离散因子 `1-exp(-dt/tau)`；桨距和转速参考命令按每秒速率乘 dt 积分。

八维观测按顺序为：

1. 功率 / 5 MW；
2. 实际转速 / 最大转速；
3. 桨距 / 25 deg；
4. 风速 / 配置最大风速；
5. 已公布目标功率 / 5 MW；
6. 转速参考状态 / 最大转速；
7. 参考滤波状态 / 5 MW；
8. 剩余回合比例。

动作数值区间仍为 `[-0.5,0.5]`、`[-0.1,0.1]`；在 v2 中单位分别为 deg/s 和 rad/s²，代表桨距变化率、转速参考变化率。tau=5 s 是假设。

每一步：观测含当前目标 → 控制器动作 → 推进执行器并读取下一时刻风 → 算功率 → 对比动作前已公布的目标计算奖励 → 用新风生成下一目标 → 返回新观测。`info.reference_applied_w` 才是本步奖励/评估所用目标，不能用 `reference_next_w` 替代。

可利用功率由风速以及固定控制域内 128×101 转速/桨距网格的最大稳态功率近似得到，独立于当前策略动作；它表示一个采样可行的稳态运行点，并非考虑执行器响应后下一秒必定可达的功率。

参考复用 `ReferencePowerGenerator`：20% headroom、20 s 低通、上下各 50 kW/s。当前参考可能因下一秒降风而不可达，记录 `target_exceeds_steady_availability`；下一参考若因可利用功率下降而必须越过下降爬坡限制，会记录 `reference_availability_clipped`。两类事件都不隐藏。目标优先遵守当前可利用功率约束，不承诺任何情况下都能同时满足爬坡和动态可达性。

回合是带剩余时间观测的有限时域任务，600 步后 `terminated=True`；结束后必须 reset。

## 5. 运行命令

从项目根目录运行；不安装新依赖。下列输出目录是新运行的示例名称，若已存在请换后缀。

只生成风况统计与 P 基准回放：

```powershell
.\.venv\Scripts\python.exe -B optimization_control/ppo_single_turbine/wind_workflow.py --output-dir optimization_control/experiments/20260913_kaimal_demo_next --samples 32
```

正式训练入口（196608 步是实验起点，不保证收敛）：

```powershell
.\.venv\Scripts\python.exe -B optimization_control/ppo_single_turbine/train.py --wind-config optimization_control/ppo_single_turbine/configs/stochastic_wind_v1.yaml --output-dir optimization_control/experiments/20260913_kaimal_training_next --run-tag kaimal_v2 --total-timesteps 196608
```

用新训练模型做回放；必须与模型元数据的完整环境配置一致：

```powershell
.\.venv\Scripts\python.exe -B optimization_control/ppo_single_turbine/wind_workflow.py --output-dir optimization_control/experiments/20260913_kaimal_eval_next --model optimization_control/experiments/20260913_kaimal_training_next/kaimal_v2_seed42.pt
```

从磁盘重新加载本次已导出风况，复现短训练模型的回放：

```powershell
.\.venv\Scripts\python.exe -B optimization_control/ppo_single_turbine/wind_workflow.py --output-dir optimization_control/experiments/20260913_kaimal_replay_next --samples 4 --model optimization_control/experiments/20260913_kaimal_ppo_smoke/kaimal_smoke_v2_seed42.pt --replay optimization_control/experiments/20260913_kaimal_wind_validation/wind_stationary.csv optimization_control/experiments/20260913_kaimal_wind_validation/wind_ramp.csv optimization_control/experiments/20260913_kaimal_wind_validation/wind_gust.csv
```

如果用验证集调参，加 `--split validation`；最终 test 场景不用于调参。每个示例回放是一个低风速分层场景，不能用三条回放概括 6–10 m/s 全域性能。频谱检查的每类 32 条集合则覆盖四个风速分层。

所有产物保存在指定目录：`config.yaml`、`metrics.csv`、`summary.txt`，以及可再生的轨迹、JSON、PNG；训练另含 `.pt` 和同名模型 JSON（完整配置、观测名称、归一化比例）。使用 CSV 日志，不依赖 TensorBoard。

测试：

```powershell
.\.venv\Scripts\python.exe -B -m unittest discover -s optimization_control/tests -p test_*.py
.\.venv\Scripts\python.exe -B -m unittest optimization_control.ppo_single_turbine.test_baseline
```

## 6. 本次验证结果及组会口径

- 49 项优化框架/风况测试及 7 项旧单机 PPO 回归通过。
- 六份磁盘回放（3 场景 × 2 控制器，各 600 步）的全部轨迹列与首次评估精确一致。
- 新风况下实际完成 8192 步、2 个并行环境、12 个完整回合的 PPO smoke；日志有有效回合回报，模型成功保存并加载。
- 三类场景各 32 条独立记录：频谱比值 0.984–0.996；均方值与离散带限谱积分比值 0.992–1.002。每类演示轨迹的拒绝次数均为 0。
- 本次三条同风况回放，P 基准 RMSE 约 151–156 kW，短训练 PPO 约 497–586 kW；PPO 仍未学会有效跟踪。这是 smoke 结果，不是算法性能结论。
- P 基准只调桨距，PPO 调两个量：轨迹和目标相同，但这不是同动作权限的算法优劣对照。后续应做同权限 PI/调度基准和正式训练。
- 风况统计图的四列依次为时间序列、湍流分量直方图、自相关和 PSD；三行是平稳、慢变化、阵风。图中英文标签避免当前中文字体依赖。

可在组会上说：已经完成基于 Kaimal 谱的可复现随机风况生成与单机 PPO 接入，支持慢变化、阵风、轨迹文件回放和统计验证；下一步是正式训练和强化基准，而不是已经证明 PPO 更好。
