## 一、研究背景：为什么要做风电场控制

### 1.1 尾流效应——风电场效率的核心瓶颈

当上游风机从风中提取能量后，其下游会形成风速降低、湍流增强的区域，即**尾流（wake）**。尾流导致下游风机的来流条件恶化，造成功率损失：

- 单台下游风机功率可因尾流**降低 60%** [P6]
- 全场年发电量损失可达 **20%-30%**（以丹麦 Horns Rev 海上风电场为例）[P1][P6]
- 丹麦 Horns Rev 风电场因尾流效应每年损失约 **20%** 的发电量 [P1]

### 1.2 传统"贪婪控制"的局限

目前工业界通用做法是**贪婪控制（greedy control）**：每台风机各自最大化自己的功率输出，不考虑对下游风机的影响。这导致：

- 上游风机全力发电 → 尾流最强 → 下游风机"吃不饱"
- 全场总功率并非最优，存在 **5%-54%** 的可提升空间 [P6]

### 1.3 风电控制的三条技术路线 [P6]

| 控制策略 | 原理 | 成熟度 |
|----------|------|--------|
| **功率降额（power de-rating）** | 上游风机主动降低出力，减少尾流强度 | 最早提出，研究充分 |
| **偏航尾流重定向（yaw-based wake redirection）** | 上游风机偏航，把尾流"甩"到旁边 | **当前最活跃，与本文项目直接相关** |
| **浮式风机重定位（turbine repositioning）** | 移动风机位置避开尾流 | 仅适用于漂浮式海上风电，研究较少 |

本文项目聚焦于第二种策略：**通过主动偏航控制实现尾流重定向，配合变桨控制实现全场功率优化**。

## 二、优化控制是什么——从定义到本项目

### 2.1 优化控制的数学定义

**控制** = 给定一个动态系统，通过调节某些输入（控制量），使系统的输出达到期望值。

**优化控制** = 控制的方式不止一种，从所有可行方案中找出**最好**的那种。

数学上，优化控制问题包含五个要素：

| 要素 | 符号 | 含义 | 风电场景中的对应 |
|------|------|------|-----------------|
| **状态** | `s` | 系统当前的情况 | 功率、转速、桨距角、风速、尾流状态 |
| **动作** | `a` | 可以调整的旋钮 | 桨距角变化量、转速变化量、偏航角 |
| **动力学** | `s' = f(s, a)` | 施加动作后状态如何变化 | 风机功率方程 + 尾流传播方程 |
| **目标函数** | `J = Σ r(s, a)` | 要最大化或最小化的量 | 功率跟踪误差最小化 + 全场功率最大化 |
| **约束** | `g(s, a) ≤ 0` | 不能违反的限制 | 桨距角范围 0°-25°、转速上限、电网功率上限 |

一句话定义：**优化控制就是，在约束条件下，找到从状态到动作的最优映射 `π*(a|s)`，使得累积目标函数最优。**

### 2.2 强化学习视角下的优化控制

传统优化控制（如 MPC）需要**已知动力学模型** `f(s, a)`。但在风电场中：

- 尾流传播是非线性、高维、随机的 → 精确解析模型几乎不存在
- 现有模型要么精度低（Jensen）要么太慢（LES/CFD）

**强化学习（RL）提供了一条绕开建模的路径**：

```
传统优化控制：                    RL 优化控制：

已知 f(s,a) → 数学优化 → π*       环境（黑箱）→ 试错学习 → π*

需要精确模型                      不需要模型
模型误差 = 控制误差                从数据中学，越学越好
```

RL 把优化控制问题转化为：

> 智能体在环境中反复执行动作、观察结果、获取奖励/惩罚，通过大量交互逐渐学会：在什么状态下该做什么动作，才能让长期累积奖励最大。

这就是 PPO 和 MADDPG 在项目中扮演的角色——它们是**求解这个 RL 优化控制问题的具体算法**。

### 2.3 本项目优化控制问题的精确表述

**场景一：单风机功率跟踪（PPO，步骤四）**

```
目标：让单台风机精准跟踪电网下发的功率指令

  状态 s：当前功率 P、转速 ω、桨距角 β、来流风速 U
  动作 a：Δ桨距角、Δ转速
  奖励 r：-(P_target - P_actual)² - λ·(动作变化量)²
          ↑ 功率跟踪误差惩罚    ↑ 动作平顺性惩罚

  目标：找到策略 π*，使 Σγᵗ·r_t 最大
```

**场景二：全场多机协同（MADDPG，步骤五）**

```
目标：多台风机协同，在满足全场总功率指令的前提下，最小化尾流损失

  每台风机 i 是一个智能体：
    观测 o_i：自己的 P, ω, β, U + 邻居风机的偏航角信息
    动作 a_i：自己的偏航角、桨距角

  全局奖励 R：-(P_total_target - ΣP_i)² - α·Σ(功率波动) + β·Σ(下游风机功率)
               ↑ 全场功率跟踪          ↑ 平抑波动      ↑ 保护下游

  目标：找到各风机的策略 π*_i，使全局累积奖励最大
  训练：critic 看全局信息，actor 只看局部信息（MADDPG 框架）
  执行：每台风机用自己的 actor，不看全局就能决策
```

## 三、风电场控制方法分类

根据 Dong et al. (2022) 的综述 [P1]，风电场控制方法可按以下维度分类：

### 2.1 按模型依赖度

```
模型驱动 (Model-based)                 数据驱动/无模型 (Model-free)
    │                                       │
    ├─ MPC (模型预测控制)                    ├─ Bayesian Ascent (贝叶斯上升)
    │   └─ 需要解析风场模型                  │   └─ 概率优化，不要模型
    ├─ SCP (序列凸规划)                     ├─ Game Theory (博弈论)
    ├─ GA/PSO (遗传/粒子群)                 ├─ Extremum Seeking (极值搜索)
    └─ 特点：依赖模型精度                    └─ **Reinforcement Learning (强化学习)** ← 本文项目
        模型误差 → 控制性能下降                   特点：不需要解析模型
                                                  从数据中自主学习
```

### 2.2 模型保真度分级 [P1]

| 级别 | 代表模型 | 精度 | 计算量 | 适用场景 |
|------|----------|------|--------|----------|
| 低保真 | Jensen, FLORIS | 低（忽略动态） | 毫秒级 | 布局优化、初步控制设计 |
| 中保真 | WFSim, Ainslie | 中（2D简化NS） | 秒-分级 | 控制导向建模 |
| 高保真 | **SOWFA, PALM** (LES) | 高（全3D LES） | **小时-天级** | 验证基准、数据生成 |
| **新趋势** | **PINN + DL 代理模型** | 高精度 + 毫秒级 | **训练慢、推理快** | **在线控制（本文项目路线）** |

> 与你项目的直接关联：申报书步骤一用的 OpenFOAM + LES 对应高保真；步骤二/三的 POD+PINN 对应表格最后一行"新趋势"。

### 2.3 控制目标分类 [P1]

1. **风场布局优化**：优化风机位置（建设前），用 GA/PSO 等
2. **全场功率最大化**：运行中最大化总发电量，用 MPC/SCP/RL
3. **疲劳载荷最小化**：减少机械损耗、延长寿命，通常和功率目标联合优化
4. **功率参考跟踪**：电网下发电功率指令，风场必须精准响应——**这正是本文项目核心目标**

## 四、基于强化学习的风电场控制

### 4.1 PPO：单风机智能控制的核心算法 [P3]

**核心思想**：策略梯度方法，通过"clip"操作限制每次策略更新幅度，防止训练崩溃。

**关键公式（Clipped Surrogate Objective）**：

```
L_CLIP(θ) = E[min(r_t(θ)·A_t, clip(r_t(θ), 1-ε, 1+ε)·A_t)]
```

- `r_t(θ)` = 新旧策略的概率比，初始值为 1
- `A_t` = 优势函数（动作比平均好多少）
- `ε` = 剪切范围（典型值 0.2）
- 当 A_t > 0（好动作）：限制概率比不超过 1+ε，防止过度"自信"
- 当 A_t < 0（坏动作）：限制概率比不低于 1-ε，防止过度"惩罚"

**为什么选 PPO（而非 DQN/DDPG/TRPO）**：
- 连续动作空间原生支持（桨距角和转速是连续值）
- 比 TRPO 简单得多（只需一阶优化，不需要共轭梯度）
- 比 DDPG 训练更稳定，对超参数不太敏感
- 实验证明在连续控制任务（MuJoCo 机器人）上全面优于 A2C、TRPO、CEM 等 [P3]

**与你项目的适配**：单台风机功率跟踪 → PPO 学习"当观测到功率偏低且风速足够时，减小桨距角 + 提高转速"

### 4.2 MADDPG：多风机协同控制的框架 [P4]

**核心创新**："集中训练、分布执行"（Centralized Training, Decentralized Execution）

```
训练阶段（可以用全局信息）：
  Critic 看到所有风机的观测 + 动作 → 评价每台风机"你对全场好不好"
  Actor 看到自己的局部观测 → 决定自己的动作

执行阶段（只能用局部信息）：
  只用 Actor，每台风机独立决策
```

**MADDPG 梯度公式**：
```
∇J(μ_i) = E[∇μ_i(a_i|o_i) · ∇a_i Q_i(x, a_1, ..., a_N)]
```
- `μ_i`：风机 i 的策略（actor），只依赖自己的观测 `o_i`
- `Q_i`：风机 i 的集中式评价器（critic），看到所有人的动作
- `x`：全局状态信息（训练时可用，执行时不需要）

**解决的核心问题**：
- 多智能体同时学习 → 环境非平稳 → 传统 RL 不收敛
- MADDPG 方案：只要知道所有人的动作，环境就是平稳的 `P(s'|s, a_1,...,a_N)`
- 不需要知道别人的策略（可以学习近似模型 `μ̂_φ`）

**与你项目的适配**：多台风机 = 多个智能体，各自决定偏航角和桨距角。MADDPG 让风机学会"牺牲一点自己，换取全场更多发电"。

### 4.3 实战案例：DDPG 风电场尾流控制 [P2]

Dong et al. (2021) 用 DDPG（PPO/MADDPG 的前辈）实现了风电场尾流重定向控制，是最接近你项目的实战参考：

**技术方案**：
| 组件 | 设计 |
|------|------|
| RL 算法 | DDPG + Reward Regularization (RR) 模块 |
| 动作空间 | 每台风机的偏航角设定值 |
| 奖励信号 | 全场总功率（归一化 + 时间平均） |
| 训练数据 | 90 组固定偏航角下的 1000 秒 LES 仿真 |
| 计算量 | 每组仿真需 256 CPU 核 × ~44 小时 |
| 仿真工具 | SOWFA (OpenFOAM-based) + TensorFlow |

**关键创新——Reward Regularization（奖励正则化）**：
- 直接用瞬时功率做奖励有两个问题：(1) 风速波动引入偏差；(2) 尾流传播是动态过程，瞬时功率不是稳态
- 解决方案：用上游风机在贪婪策略下的功率做归一化基准，用时间平均替代瞬时值
- 实现了无需风速测量的鲁棒控制

**关键结果**：
- 相比贪婪策略，全场总功率**平均提升 15%**
- 数据驱动、无模型（不需要解析尾流模型）
- 可离线预训练 + 在线微调
- 只需稀疏训练数据（90 个固定偏航角工况，不需要连续随机变化）

> **对你项目的启示**：你也需要设计奖励函数时考虑风速归一化；训练数据可以不用太多（90 组就够）；PPO 替换 DDPG 后训练会更稳定。

## 五、风电场控制的核心物理基础 [P5]

Boersma et al. (2017) 提供了风电场控制入门的完整知识框架。以下是与你优化控制模块直接相关的关键公式和概念：

### 5.1 风机功率方程

```
P = 1/2 × ρ × A × CP(λ, β, γ) × U³
```

| 符号 | 含义 | 你的控制变量？ |
|------|------|---------------|
| ρ | 空气密度 (~1.225 kg/m³) | 不可控 |
| A | 扫风面积 (πR²) | 不可控（风机固定） |
| **CP** | **功率系数** | **可通过 λ, β, γ 影响** |
| U | 来流风速 | 不可控，但可通过偏航改变下游的 U |

### 5.2 三大控制变量

| 变量 | 符号 | 调节速度 | 控制目标 |
|------|------|----------|----------|
| 桨距角 | β (pitch) | ~10°/s | 直接影响 CP，进而影响功率 |
| 叶尖速比（→转速） | λ (tip-speed ratio) | 通过发电机转矩调节 | 影响 CP |
| 偏航角 | γ (yaw) | 慢（液压电机） | 改变尾流方向，影响下游 U |

### 5.3 运行区域 [P5]

```
功率 ↑
     │        Region II        Region III
额定 ┤          /‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾
     │         /                  (额定功率，变桨控制)
     │        /
     │       /  (最大功率追踪，
     │      /    转矩控制)
     │     /
     └────┴────────────────────→ 风速
     切入                      额定    切出
```

- **Region II**（低风速）：目标是尽可能多发电（最大功率追踪）——跟踪问题
- **Region III**（高风速）：目标是稳定在额定功率（扰动抑制）——调节问题
- 你的项目关注 **Region III**（电网调度指令通常 ≤ 额定功率）

## 六、定量对比：现有方法的效果 [P6]

Kheirabadi & Nagamune (2019) 对数十篇风电场控制研究做了定量统计。关键数据：

### 6.1 不同控制策略的功率提升对比

| 策略 | 典型全场功率提升 | 验证方式 |
|------|-----------------|----------|
| 功率降额（轴向诱导控制） | 1%-10% | 仿真为主，少量风洞实验 |
| 偏航尾流重定向 | **5%-25%** | 仿真 + 风洞 + 部分现场试验 |
| 浮式重定位 | 10%-30%（仿真估算） | 纯仿真 |

> 你的项目选择了潜力最大的偏航尾流重定向路线。

### 6.2 不同控制算法的对比

| 算法 | 模型依赖 | 功率提升 | 计算效率 | 适应不确定性 |
|------|----------|----------|----------|-------------|
| MPC (模型预测控制) | 需要解析模型 | 5%-15% | 中 | 差（模型失配时性能下降） |
| Bayesian Ascent | 无模型 | 4%-10% | 低（开环搜索慢） | 中 |
| Game Theory | 需要简化模型 | 5%-25% | 中 | 中 |
| **RL (DDPG/PPO/MADDPG)** | **无模型** | **15%+** [P2] | **低（推理快）** | **强（数据驱动自适应）** |

### 6.3 影响控制器性能的关键因素 [P6]

1. **尾流模型的保真度**：用高保真 CFD 验证的结果比用简化模型验证的**低 30%-50%**
2. **风速条件**：稳态均匀风下的结果显著优于动态非均匀风
3. **通信架构**：集中式 > 分布式 > 完全分散式（但通信成本递增）
4. **风场规模**：风场越大，协同控制的收益越大

> **对你项目的警示**：很多论文用简化模型报出的"提升 20%"在真实 CFD 中可能只剩 5%-10%。这就是你的项目为什么要做步骤六（虚实闭环验证）。

## 八、对本文项目下一步的启示

1. **先从简化环境做起（P5 公式 + P3 PPO）**：风机功率方程 `P = 1/2·ρ·A·CP·U³` 加上 Cp 经验公式即可搭建第一个 RL 环境——不需要等 CFD 数据
2. **奖励函数设计参考 P2**：用上游风机功率做归一化基准，时间平均去除动态噪声
3. **PPO 超参数参考 P3**：clip ε=0.2，MLP 2×64 hidden units，Adam optimizer
4. **多机阶段参考 P4 MADDPG**：集中 critic 用全场信息训练，分散 actor 执行时只用局部观测
5. **定量目标参考 P6**：全场功率提升 5%-15% 是合理的预期范围；声称 20%+ 需要谨慎
6. **验证标准参考 P1+P2**：最终必须用高保真 CFD（SOWFA/OpenFOAM）或物理实验验证，简化模型结果不可直接用

### 9.2 阶段一：强化学习环境构建（历史规划；解析环境与 T1 PPO 已于 2026-08-08 完成）

这是所有后续工作的基础。一个 RL 环境 = 状态空间 + 动作空间 + 动力学 + 奖励函数。

**第一版：简化风机环境（不依赖任何队友，现在就能做）**

```
┌─────────────────────────────────────────────┐
│            SimplifiedTurbineEnv             │
│                                             │
│  输入动作 a：                                │
│    Δβ  (桨距角变化量)   范围 [-0.5°, +0.5°]  │
│    Δω  (转速变化量)     范围 [-1 rpm, +1 rpm]│
│                                             │
│  动力学（解析公式）：                         │
│    P = 0.5 × ρ × A × Cp(λ,β) × U³           │
│    Cp = 0.5176×(116/λi-0.4β-5)×e^(-21/λi)   │
│         + 0.0068λ                           │
│    1/λi = 1/(λ+0.08β) - 0.035/(β³+1)        │
│    J × dω/dt = Ta - Tg                      │
│                                             │
│  输出观测 s：                                │
│    [P, ω, β, U, P_target]                   │
│                                             │
│  奖励 r：                                    │
│    -(P_target - P)² - 0.1×(Δβ² + Δω²)       │
│                                             │
│  风速 U：外部脚本生成（阶跃/正弦/随机）        │
└─────────────────────────────────────────────┘
```

**第二版：PINN 驱动环境（等 PINN 组交付后升级）**

```
┌─────────────────────────────────────────────┐
│            PINNTurbineEnv                    │
│                                             │
│  同第一版，但动力学部分替换为：               │
│    s_{t+1} = PINN_forward(s_t, a_t)        │
│                                             │
│  优势：精度接近 CFD，速度毫秒级               │
│  要求：PINN 组提供 TorchScript .pt 模型       │
└─────────────────────────────────────────────┘
```

**第三版：多风机协同环境（阶段五）**

```
┌─────────────────────────────────────────────┐
│          MultiTurbineFarmEnv                 │
│                                             │
│  N 台风机，每台是一个智能体                   │
│  全局状态包含所有风机位置和尾流信息           │
│                                             │
│  奖励：                                      │
│    R_total = -(P_ref - ΣP_i)²               │
│              + β × ΣP_downstream           │
│              - α × Σ(功率波动)              │
│                                             │
│  遵循 PettingZoo / MultiAgentEnv 接口       │
└─────────────────────────────────────────────┘
```
