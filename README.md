# 风电流场智能感知与智能调控 · 项目仓库

> 西安交通大学 · 国家重点领域大学生创新训练项目《融合数据-物理驱动的风电流场智能感知与智能调控研究》（2026.04–2027.06）
> 导师：李良星 副教授

**这个仓库是什么**：一个小组把"用 Fluent 算流场 → 训 PINN 代理模型 → 跑多智能体优化控制 → 在可视化界面里看结果"这条链真正搭起来的全部过程记录，包括代码、数据、交付件、决策和踩过的坑。

## 一句话现状（2026-10-24）

> **软件链路通了，物理精度还没建立。**

五个模块都能跑、能对上接口、能演示；但作为训练标签的高保真流场还不够准（CFD 网格解析不了串列尾流），所以所有精度类结论**只能叫"合成标签下的工程近似"**，不能叫物理验证。

**当前唯一任务：中期答辩**（7 分钟 / 14 页）。其余工作全部暂停。

## 仓库规矩（不遵守会被门禁拦下）

1. **提交前跑门禁**：`python3 ci/repo_quality.py`，必须 0 error。它会查死链、检查 Office 文件有没有 Markdown 镜像、校验 `SHA256SUMS.txt`、拦超大文件。
2. **Office / PDF 一律带 `.md` 镜像**：放好文件后跑 `python3 tools/markitdown_sync.py`。
3. **交付包只留解压件**：zip 逐文件核对 sha256 后删除，zip 本体的 sha 记进对应 README。
4. **超过 50 MiB 的文件不进 git**：走 GitHub Release，按 [`ADR-2026-003`](docs/decisions/) 的大文件口径，并在清单里登记。
5. **个人材料按内容主责归档**到 `materials/<姓名>/`，不按谁上传的归档。
6. **数字只有一个权威来源**：写进材料前先查 [`docs/evidence/`](docs/evidence/README.md) 和 [`materials/README.md`](materials/README.md) §5。

完整规则见 [`CONTRIBUTING.md`](CONTRIBUTING.md) 与 [`materials/README.md`](materials/README.md) §2。

## 数据口径（四个标签，用错会出事）

| 标签 | 含义 | 能不能当结论 |
|---|---|---|
| **真实** | 有明确离线计算、来源或实验记录 | 可以，但要带条件 |
| **代理** | 简化模型或浏览器端推算（FLORIS、PINN 输出都属此类） | 只能当近似 |
| **演示** | 界面展示用的确定性数据 | 不能当场站值 |
| **示意** | 几何、构图、概念表达 | 不能当测量 |

**本项目当前没有一条"实测"级别的风场数据。** 所有功率与尾流结论的最上游都是 FLORIS（工程尾流模型），再往上一层的 Fluent 结果尚未达到可用精度。

## 已知的坑（后来者最容易踩的六个）

1. **本仓库是浅克隆**。`.git/shallow` 存在时，`git log --follow` 和 `git blame` 会给出**错误答案**。查历史用 `gh api repos/sunccchengze/FENGDIAN_2026/commits?path=<文件>`。
2. **`main` 在 2026-10-24 被整仓覆盖上传过**（`f2a6f4f` 是单根提交）。402 个提交的历史已不在 main 上，旧对象目前仍在但无 ref 指向。
3. **同一个模型，交付包和使用记录可能分开在两个目录**。判断"某件事做没做"，不能只看交付目录，要去下游找有没有人跑过。
4. **文档会自我加固**。写在文档里的数字，读三遍就像真的了。**每个关键数字都要能追到原始文件**。
5. **`viz/figures_nature/` 是 3×3 旧口径**，不能当 1×3 结果用。
6. **多个 README 里抄着同一组数字**，改的时候容易漏。数字只认权威来源。
