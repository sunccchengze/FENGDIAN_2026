## 0. 为什么「删掉旁边两列」不等于完成（用户 2026-10-05 质疑，实证回答）

几何上确实就是删两列——R41-A 之后，切 1×3 已经是一行开关（`?layout=1x3` / `TWIN_LAYOUT=1x3`）。
**但「删两列」会留下三类不会跟着删的东西**，本轮的全部工作量就是这三类：

### 0.1 第一类：跟着「9」走、删列后直接崩溃的代码（实证）

`TWIN_LAYOUT=1x3 npm run selftest` 在 **import 期即崩**：

```
TypeError: Cannot read properties of undefined (reading 'x')
    at towerForward (src/scene/hotkeys.ts:41)   // const u = FARM[i]，i 最大到 8
```

热键表在模块加载时就用 `FARM[0..8]` 建 9 个机位；1×3 只有 3 台，`FARM[6]` 是 `undefined`。
这不是断言失败、不是画面错，是**程序起不来**。写死下标/写死循环的完整清单（2026-10-05 grep 实测）：

| 模块 | 写死内容 | 1×3 后果 | 本轮改法 |
|---|---|---|---|
| `scene/hotkeys.ts` | 9 个热键机位 1–9 ↔ T01–T09；selftest 断言「恰 9 个」 | **import 期崩溃** | 1/2/3 = 三机高俯、4/5/6 = 平视、7/8/9 = 低仰（沿用三种取景语法）；断言改「= 布局机位数」 |
| `scene/introProfile.ts` | 34 s 开场 13 航点写死 `FARM[2]/[4]/[6]`（10 处） | 航点落空/穿越空景 | 1×3 改沿列纵深：北来流空域 → 掠 T01 → 侧绕 T02 → 低机位停 T03 前；3×3 路径整表留 `byLayout` |
| `scene/CameraRig.tsx` | 书签/默认注视点 `FARM[6]`（1 处） | 注视空位 | 语义选择器（最近景机组） |

| `audio/audioModel.ts` | 「9 机全上 Panner 太贵」的声部裁决 | 沿用裁剪（浪费） | 3 机**全部上 PannerNode**（HRTF 方位更准、预算更宽）；`qa_audio*.mjs` 口径同步 |

R41-A 已经消掉的是**静默错**的那一类（`FARM_RATED_MW=45`、贪心 `row<3`、DTAP `length===9`、滑杆 9 根——这些不崩，只是**错得安静**，更危险）。本轮消掉**崩溃与错看**的这一类。

### 0.2 第二类：被验证过的数字（删列不会让它们消失，只会让它们变错还挂绿灯）

3×3 不只是画面，它是**目前唯一被验证过的真值几何**：

- `selftest` 的 V&V 断言对着 FLORIS 3×3 实算表：`none 8108.08 kW ±5%`、`unified+30° 9060.03`、`独立寻优 24.04% ±3pt`、G3 三组 3×3 断言；
- 钦定口径 +24.04% / 8095.15 kW / 97.97% 写在 README、docs/03、界面角标三处；
- `viz/` 封板数据、软著与答辩材料引用的都是这套几何。

1×3 的寻优搜索空间是 3 个偏航变量而不是 9 个，**增益数字必然不同**。删列而不出新真值 = 拿 3×3 的数字给 1×3 用 = 触犯红线「不虚构数据来源」。所以本轮的另一半是 **§3 新 oracle**，不是可选件。

### 0.3 第三类：团队决议不许删

[`docs/13`](../13_0919组会决议_三风机改造方案与3x3留档.md) 决议 4（2026-09-19 组会）：**3×3 不删，留档，视研究进度可能调回**；
落地形式 = 留档 tag `twin-3x3-archive-20260919` + 「布局可切换」设计。删列即违反自己组的决议，
也丢掉「导师要看回九机阵」时的退路。所以答案是**参数化**，不是删除。

> 一句话回应用户：删两列是**一行**；让删完之后的 20 处消费者、9 组被验证数字和一条团队决议
> 仍然成立，才是这一轮。R41-A 把「一行」做出来了，R42 把「仍然成立」做完。

## 3. 新 oracle 设计（#2，docs/13 §4.4 原文落地）

- 几何：三机串列 `[(0,0),(0,632),(0,1264)]`（= 3×3 中列，round41 守卫③已锁）。
- 工况：8 m/s 北来风 × {上游偏航扫描 −30…+30 步 5°、中游偏航扫描同、统一偏航同、逐机贪心最优}。
- 环境：`pip install floris==4.6.6`（与 3×3 oracle 同版本，保证口径可比）。
- **交叉校验（免费的正确性检查）**：1×3 `none` 与「统一偏航」工况的逐机功率，应等于
  3×3 oracle 中列切片（北来风下三列互不干扰）；差异 > 0.5 kW 就要解释。存证进
  [`r41_equiv_3x3.json`](r41_equiv_3x3.json) 的同款 JSON。
- 产出：`floris_gch_oracle_v1.json` 追加 `tandem3` 块 + `SHA256SUMS` 更新 + 门禁校验。

## 3.3 交叉校验结果与归因修正（2026-10-05 实测，FLORIS 4.6.6 GCH）

`generate_floris_gch_oracle.py` 新增第 4b 节跑通（`pip install floris==4.6.6`，17 s），
`tandem3` 块入库（`floris_gch_oracle_v1.json` +127 KB 档 / `florisGchOracle.ts` 同步；
**旧 section 逐位不变**，只新增 `tandem3`）。

| 工况（8 m/s 北来风） | 结果 |
|---|---|
| none 总功率 | **2702.22 kW**，逐机 [1754.0, 439.0, 509.2] |
| 统一偏航最优 | +20° → 3107.1 kW（+14.99%） |
| 上游扫描最优 | +30° → 3060.0 kW |
| 中游扫描最优 | +30° → 2874.6 kW |
| 逐机贪心终态 | **[30, 25, 0] → 3299.8 kW，+22.11%**（3×3 是 24.04% —— 数字确实随布局变，坐实「1×3 不得沿用 3×3 数字」） |

**交叉校验（中列切片 vs 独立三机串列）**：

| 工况 | 1×3 逐机 | 3×3 中列切片 | 最大差 |
|---|---|---|---|
| none（零偏航） | 1754.0/439.0/509.2 | 1754.0/439.2/509.7 | **0.472 kW**（≈0，列间零偏航互不干扰，成立） |
| 统一 +30° | — | — | **12.08 kW**（偏航后尾流横偏跨列侵入中列，中列切片**失效**） |

→ 占位数据策略（中列切片当 1×3 代理）的适用边界被**定量**：零偏航下 ≤0.5 kW 可用，
偏航工况必须用独立 tandem3（本 oracle 已提供）。与 R41 的占位标签【1×3 代理·源自3×3中列】
完全一致，现在有了数字支撑。

**归因修正（重要）**：立项时把「下游 T03(509.2) 反高于中游 T02(439.0)」判为 Jensen 顶帽
代理的缺陷（"真实物理必单调"）。**FLORIS 实算同样非单调**（上表 none 逐机），真实原因是：
T02 正对 T01 尾流核心（5D 衰减最强），T03 处 T01 尾流 10D 已扩散 + T02 低推状态自身尾流
更弱，叠加后净衰减反而更小。且 Jensen 代理与 FLORIS 逐机差 **≤0.5 kW**（none 工况）——
R18 标定不只对齐总功率，对串列几何的逐机功率也是准的。selftest 相应注释已改，
**不再把非单调当代理缺陷**。
