# 项目历史总账（时间戳整理 · 2026-10-26）

> **这份文件是什么**：把 2026-03 立项到 2026-10-26 的全部经过，按**时间戳**压成一份可独立阅读的总账。
> 它取代的不是「所有旧文档」，而是**旧文档里的时间线部分**：什么时候、谁、做了什么、结论是什么、后来被谁推翻。
>
> **为什么要做这份**：仓库里 532 份 `.md`、236 张轮次截图、33 份 `round*.md`，真正会被回看的不足十分之一。
> 而新人（或下一任 agent）读它们要花掉一整天，还容易把 8 月的口径当成 10 月的。
> 所以：**叙事收进这一份，过程原件按 `docs/ARCHIVE.md` 的规则离场或封存**。
>
> **这份文件不替代的**：`docs/evidence/`（结论的证明）、`docs/decisions/`（为什么这样定）、
> `optimization_control/`（代码与实验记录）、`materials/`（他人交付原件）。这四类即使旧也不许删——它们是证据本身。

## 0. 先记住三件事，否则读下去会乱

### 0.1 有三条互相错位的时间轴

| 轴 | 含义 | 例子 |
|---|---|---|
| **事件日期** | 事情实际发生的那天 | 田铭雨 8-25 在群里发《fluent 仿真疑问》 |
| **入库日期** | 文件被提交进仓库的那天 | 该 docx 直到 9-20 才归档进 `materials/` |
| **自述日期** | 文件正文自己写的日期 | 轮次文档常见「写于 8-30、实际 9-13 才定稿」 |

**判断「什么时候发生的」用事件日期；判断「我们现在什么时候知道的」用入库日期。** 两者差 3 天到 3 周都正常。

## 6. 已经说错过的四件事（记住错法，比记住对法有用）

1. **「17/20 场优于 PI」→ 实为 12 胜 6 负。** 错因：把每个 `case_id` 的 3 次重复 run 当成 3 个独立样本。正确口径是**先按 case 在 3 次 run 上取均值**，再比。
2. **「桨距超上限 11.8 倍 / 82% 步越界」→ 已撤回。** 错因：① 把 `command_*`（归一化动作 −1…1）当物理角速度与 rad/s 上限相除；② 按 `case_id` 分组后排序，相邻两行来自不同 run，`np.diff` 造出不存在的步进。**必须按 `(case_id, run_id)` 分组，且只用物理状态列。**
3. **「三机串列 CFD 数据可用」→ 判否。** 盘面平均取样口径不可靠：648 个盘面点里四到五成越界；T1→T2 只降 0.2%，T2→T3 却降 34%，两种汇总互相矛盾；`wake_profiles.csv` 速度区间 −19.6…+30.8 m/s（U∞=9）。**能说的只有一句：两套湍流模型单机功率差 2.7%，且都与 FLORIS 同配置差 10% 以内。**
4. **「3×3×20 = 240 行」→ 实为 180。** 记忆会自我加固，越读越像真的。
