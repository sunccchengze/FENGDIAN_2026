## 1. 背景

`twin/`（AEOLUS TWIN）自 2026-08-19 起按 `v1.3-final` 封板，功能与视觉冻结，只允许修 bug。

2026-10-25 用户试用当前可视化时提出两个问题：

1. **「切换按键在哪？是不是没设置。」**——事实核查：确实没有。两套几何（3×3 阵列九机 / 1×3 串列三机）
   只能通过 URL `?layout=1x3` 或构建期环境变量 `TWIN_LAYOUT` 切换，界面里没有任何入口；
   唯一能看出当前是哪套布局的地方，是左列「机组状态矩阵」面板标题里的 `Matrix 阵列 3×3` 小字。
2. **「怎么打开这里面的一个数据看板」**——主界面本身就是 10 个面板的看板；另有 `?demo=1` 的七步演示面板，
   但它在 3×3 下只显示一句「请用 `?demo=1&layout=1x3` 打开」，点到为止、不给出口。

结论：这不是 bug，是封板时按「截图/演示」场景设计、没有考虑现场交互。用户据此解冻。

## 2. 候选方案

### 方案 A · 保持封板，只用 URL 参数

- 优点：零风险，不碰 173 条自检与冻结基线。
- 缺点：答辩现场要在地址栏手打参数；演示中途想换布局等于让人退出全屏。
- 判定：**否决**（用户已明确要按钮）。

### 方案 B · 轻量切换：顶栏按钮改 URL 后整页导航（**采用**）

- 做法：`layouts.ts` 增两个纯函数 `layoutFromSearch` / `switchLayoutHref`；
  顶栏加「布局 3×3 / 1×3」按钮组，点击只改 `layout` 一个参数并 `location.assign`，其余参数原样保留；
  `?demo=1` 在 3×3 下的死胡同提示补一个「切到 1×3 串列并继续演示 →」按钮。
- 优点：用户可见可用；改动集中在 2 个组件 + 1 个纯函数模块 + CSS；场景图、机位表、告警引擎一律不动；
  自检可覆盖（纯函数 + 参数保留 12 条断言）。
- 缺点：切换是一次整页重载，会重放开场动画、丢失当前镜头与滑杆状态。
- 验证：`npm run lint` 0 警告 0 错误；`npm run selftest` 173 通过 / 0 失败；`npm run build` 通过。

### 方案 C · 热切换（不重载，React 状态驱动换场景）

- 做法：把 `ACTIVE_LAYOUT / LAYOUT / FARM / CAM_HOTKEYS / N_UNITS` 从模块常量改成 store 状态，
  9 个消费者改响应式，`Canvas` 按 `key={layout}` 重建。
- 优点：无重载、镜头可保留。
- 缺点：这 5 个常量在 89 处被引用，其中多数在模块顶层求值（`const HUB = new THREE.Vector3(FARM[...])`、
  `CAM_HOTKEYS = GRAMMAR.flatMap(...)`）；改造成本与「重建整棵场景图正确性」的回归风险，
  远大于它省下的那 1 秒重载。答辩场景不需要边走边换。
- 判定：**否决**（记录在案，未来若要做实时多布局对比再开）。

## 3. 决策

采用**方案 B**。具体口径：

- 顶栏新增 `布局 [3×3][1×3]` 按钮组，当前布局高亮、另一个可点，样式沿用「画质 / 声场」同一芯片语言；
- 点击 = `switchLayoutHref(location.href, id)` 后整页导航，**只改 `layout`，`demo / step / q / debug / hash` 全保留**；
- `?demo=1` 在 3×3 下的提示改为带出口的按钮；
- **不动**：默认布局（仍 3×3）、场景几何、机位表、数据口径、三类角标、页脚声明、时间轴语义。

## 4. 取舍理由

- 现场价值高、实现面积小：2 个组件 + 1 个纯函数模块 + 1 段 CSS，且不触碰任何物理/数据口径；
- 「默认 3×3」保持不变，历史截图与 `v1.3-final` 的取证基线全部仍然有效；
- 参数保留意味着「开着七步演示面板点切换」不会把演示丢掉——这是方案 B 相对手工打 URL 的实质优势。

## 5. 影响

- **代码**：`twin/src/scene/layouts.ts`（+3 纯函数，解析改为复用同一函数）、`twin/src/hud/Hud.tsx`（+LayoutSwitch）、
  `twin/src/demo/DemoPanel.tsx`（死胡同 → 一键切换）、`twin/src/styles/theme.css`、`twin/src/demo/demo.css`、
  `twin/scripts/selftest.mts`（+12 条断言）。合计 6 个文件，无新增依赖。
- **数据**：无。两套几何的数字仍不得混写（`docs/13`、`docs/research/round42` 的口径不变）。
- **文档**：`twin/README.md` 增「布局切换」一节；本 ADR；`docs/decisions/README.md` 索引。
- **材料**：答辩第 10 页的界面截图来自本平台，按钮会出现在成片里——**截屏前请确认当前布局与讲稿一致**
  （讲稿走 3×3 还是 1×3 见 `docs/defense`；两套数字不可混讲）。
- **维护成本**：切换逻辑集中在两个纯函数，后续若要加第三套布局，只需在 `LAYOUTS` 增加项并在这里多一个按钮。
- **未来升级路径**：若确需热切换，按方案 C 的清单做，本 ADR 届时 supersede。

退出条件（需重新打开本决策）：

1. 现场需要**不重载**地连续对比两套几何——则改走方案 C；
2. 顶栏在 1280×720 等窄高屏出现控件重叠（当前用 `@media (max-width:1440px)` 收紧右偏移，若仍重叠需重排）；
3. 用户决定**只保留一套几何**（则按钮与 1×3 一并下线，回到单布局）。
