## 二、改造目标与几何

- **目标布局 `1x3`**：3 台 NREL 5MW 沿主风向（北→南，+z）串列，T01 最上游、T03 最下游；间距 **632 m（5.02D）**；
  列位取现 3×3 的中列 `x = −100`（保持场心与升压站/海岸/取景关系不变），行位沿用 `z = −1272 / −640 / −8`。
  —— 等价于**保留 3×3 的中列、去掉左右两列**，几何上是现布局的严格子集，海床/岸线/森林/升压站/相机基准不需要动。
- **物理意义**：串列是尾流导向（wake steering）最纯粹的工况：上游偏航 → 尾流横向偏折 → 下游增益；
  `viz/` 的两机串列研究（8 m/s、5D、最优 +25°、全场 +8.13%）可直接延伸为三机串列的基线叙事；
  对应申请书阶段五"3×3 微缩风洞"的**单列试验段**（用户口径）。
- **不做的事**：不改海洋/地形/天空/声场/草地任何视觉层；不改 GCH 内核公式（它本来就是逐机顺序求解，与布局无关）。

## 三、设计原则：布局可切换，不删 3×3

```ts
// twin/src/scene/layouts.ts（新）
export type LayoutId = '3x3' | '1x3'
export const LAYOUTS: Record<LayoutId, { rowsZ: number[]; colsX: number[]; servos: number[]; label: string }> = {
  '3x3': { rowsZ: [-1272, -640, -8], colsX: [-732, -100, 532], servos: [6, 7, 3, 5, 1], label: '3×3 九机阵（FLORIS 例题场）' },
  '1x3': { rowsZ: [-1272, -640, -8], colsX: [-100],            servos: [0, 1, 2],       label: '单列三机串列（5.02D）' },
}
export const ACTIVE_LAYOUT: LayoutId = resolveLayout()   // 默认 '1x3'；URL ?layout=3x3 / 环境变量 VITE_LAYOUT 可切回
```

- `FARM` 由 `ACTIVE_LAYOUT` 生成，其余代码一律从 `FARM.length / FARM[i].row / FARM[i].col` 派生，**禁止再出现字面量 9 / 3×3**（selftest 加一条 grep 守卫）。
- 机位/锚点/开场路径/舵机映射等"按机组编号写死"的表，改为**按布局键查表**（`byLayout('3x3', …)`），3×3 那份原样搬进表里，不删。
- FLORIS 真值：3×3 的 oracle 与钦定表保留不动，新增 1×3 的 oracle；selftest 的 V&V 断言按 `ACTIVE_LAYOUT` 选对应真值组。
- 界面角标：布局属【示意】级（几何布置），角标文案随布局变化；页脚声明不变。

这样 3×3 有三重保险：Git tag（§六）、代码内切换（`?layout=3x3`）、oracle/文档不删。

### 7.1 怎么理解"维度"——数端点

- 一维（线段）2 个端点；二维（正方形）4 个；三维（立方体）8 个；四维 16 个。规律：**n 维超立方体有 2ⁿ 个端点**（每个坐标各取上界或下界）。
- 升维的构造：n 维体 = 两个 n−1 维体沿新方向"拉开"、对应端点两两相连（线段 → 正方形 → 立方体 → 超立方体）。
  会上的说法是"四维是由三维空间编出来的"。**精确表述**：四维超立方体 = 2 个立方体的 8 对对应顶点相连（所以 16 个端点）；它的"表面"由 8 个立方体（胞）围成，正如立方体的表面由 6 个正方形围成。
- **站在三维看四维：第 4 个坐标用颜色表示**（三维散点/曲面 + 色标 = 4 个自变量同屏）。会上说"回头再解释"——等用户补充后续内容。

### 7.2 高维空间的采样：先用端点把空间"钉住"

- 10 维 → 2¹⁰ = **1024 个端点**；采样点数**至少要采到 1024 个以上**，才能把设计空间牢牢限制住——先确定空间（用端点确定边界），再在里面采样。
  背后的道理：端点撑起的是参数空间的凸包，采样盖住端点，后面的代理/插值才是**内插**而不是外推。
- 推而广之：d 维至少 2ᵈ 个点，维度每加一，最少采样翻一倍 → 这就是**维数灾难**：高维情况下采样点太多，很难搞。这是后面要专门讨论的问题（降维 / 压缩输入维度）。
- **推断（agent 补，待用户确认，不是会议原话）**：这条逻辑和"3×3 改单列三机"是连着的。代理模型的输入维度 ≈ 各机偏航角 + 风速 + 风向：
  九机 → 9 + 2 = 11 维 → 至少 2¹¹ = **2048** 个端点采样；三机串列 → 3 + 2 = 5 维 → 2⁵ = **32** 个。
  把阵列缩到三机，本质上是把采样维度从 11 降到 5，让阶段二/三的 LES·FLORIS 数据库与代理模型训练的采样预算变得可行。
  （POD 是对**输出**场的降维，这里说的是**输入**参数空间的维度，是两回事。）

### 7.3 学习纪律（经验教训，写给自己）

1. **学什么都不求快。**
2. **绝对不用复制粘贴把 AI 的回答粘进来，一定要自己亲手敲一遍。** 粘进来的东西不会变成自己的。
3. 检验标准是"能不能用自己的话把最基本的概念说出来"。反面例子：会上被问"卷积神经网络 CNN 的 **C** 是什么意思"，答不上来。
   - 答案：C = **Convolutional（卷积）**，CNN = Convolutional Neural Network。"卷积"= 拿一个小窗口（卷积核）在输入上滑动、逐位置做加权求和，
     用同一组权重扫全图来提取局部特征（边缘、纹理），权重共享所以参数少、对平移不敏感。
   - 按第 2 条的规矩：这一段请自己敲一遍，再合上本页。
4. agent 侧配套做法（建议）：学习类内容只给提纲、提问和检验题，不替用户产出"可直接粘贴的笔记"；
   用户的学习笔记（`viz/PS_STUDY_*.md`、白皮书练习册等）以手敲为准，agent 不代填答案。
