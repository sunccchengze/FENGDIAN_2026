# 旧文档与作废文件索引

> **为什么有这一页**：本仓积累了 400+ 份文档，很多是过程中产生的、已经不代表现状。新读者最大的风险不是找不到东西，而是**把旧东西当成现在的**。
>
> 这一页是唯一的"旧"标签登记处。每份被标记的文档顶部也有一行 `🗄️ 历史留档` / `🚫 已作废` 徽章，指向这里。
>
> ⚠️ 2026-10-26 审计发现：[`defense/README.md`](defense/README.md) 也维护了一套并行徽章表。**新增登记一律写在本页**，`defense/README.md` 只保留一行回链，避免两处各写各的。
>
> **维护规则**：任何文档被取代时，在它顶部加徽章，并在这里登记一行。**不要删除旧文档**——答辩和审计时它们要能倒查。
>
> **2026-10-26 起补一条**：整批删除（如 `docs/research/shots/` 230 张截图）之前，必须先把它的叙事收进
> [`project/HISTORY.md`](project/HISTORY.md)，并在 [`audits/2026-10-26_仓库瘦身方案.md`](audits/2026-10-26_仓库瘦身方案.md) 留一行「哪天删的、为什么、怎么取回」。
> **HISTORY 承接叙事、ARCHIVE 承接状态、git 历史承接原件**——三者分工，不互相替代。

## 徽章说明

| 徽章 | 含义 | 该怎么用 |
|---|---|---|
| 🚫 **已作废** | 被新版本整体取代，**按它做会做错** | 只看它指向的新版本 |
| 🗄️ **部分过时** | 结构/结论部分失效，但仍有可用内容 | 挑着用，以新版本为准 |
| 🗄️ **历史留档** | 记录当时的真实状态，本身没错，只是不再是现状 | 当历史读，引用时必须注明"当时口径" |
| 🗄️ **已被取代** | 同类文档已有更新版本 | 用新版本 |

## 怎么新增一条

1. 在旧文档 H1 之后插入一行：
   ```markdown
   > 🗄️ **历史留档**（YYYY-MM-DD）｜一句话说明为什么旧了。索引：[`docs/ARCHIVE.md`](ARCHIVE.md)
   ```
   （`docs/` 下的文件用 `../ARCHIVE.md`，`docs/defense/` 下的用 `../ARCHIVE.md`）
2. 在本页对应小节加一行表格。
3. 跑 `python3 ci/repo_quality.py` 确认没死链。
