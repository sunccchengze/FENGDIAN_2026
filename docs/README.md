# 项目文档入口

`docs/` 是本项目研究过程、决策、会议、审计和证据的长期记录区，不是临时草稿堆。

## ⚠️ 先确认你要读的那份是不是旧的

本目录有大量历史文档。**读任何一份之前，先看 [`ARCHIVE.md`](ARCHIVE.md)**——被取代的文档顶部都带 `🚫 已作废` / `🗄️ 历史留档` 徽章。

| 徽章 | 含义 |
|---|---|
| 🚫 **已作废** | 按它做会做错，只看它指向的新版本 |
| 🗄️ **部分过时** | 结构失效但仍有可用内容 |
| 🗄️ **历史留档** | 记录当时状态，引用须注明"当时口径" |

## 文档分层

- `research/`：按轮次记录实验、分析、视觉验证和失败尝试（**含 R 轮次索引表与编号缺口核对**）；
- `evidence/`：记录权威数字、证据链和复现入口；
- `decisions/`：记录会改变技术或口径的长期决策；
- `meetings/`：记录会议、分工和后续动作；
- `templates/`：新建记录时使用的模板；
- `project/`：**项目级时间线主干（`TIMELINE.md`，全仓唯一的「什么时候发生了什么」入口）**，以及 GitHub Project 的字段、视图、自动化和配置状态；
- `audits/`：治理、迁移边界和自动化实现的复核记录。

> **时间线分层**：`project/TIMELINE.md` 是主干，其余 6 处是分区明细，各自只负责一个领域并已在顶部回链主干——① 会议 `materials/集体/会议时间线.md`；② 会议纪要 `meetings/README.md`；③ 群聊 `materials/集体/聊天记录/`；④ 研发轮次 `research/README.md`；⑤ 仓库治理 `12_两仓归一….md` + `audits/`；⑥ Agent 交接 根 `HANDOFF.md` / `HANDOFF_NEXT.md`。新增事件先进主干，再在分区展开。

历史文档尽量保留原路径和原始语境。新文档必须写清用途、状态、负责人、日期、来源和后续链接。

## 文件质量标准

重要文档至少要能说明：

1. 它解决什么问题；
2. 它是源文件、派生产物还是历史归档；
3. 当前是否仍然有效；
4. 事实来自哪里；
5. 读者如何验证；
6. 哪些内容不能从它推断出来。

不要在多个 README 中复制同一组容易变化的数字。数字应尽量只有一个权威来源，其它位置只做摘要并链接回来源。
