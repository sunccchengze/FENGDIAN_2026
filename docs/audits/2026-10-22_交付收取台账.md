### 3.3 唯一可用的取件通道：git

沙箱能读的只有 git 本身。所以要把内容送进来，必须**提交到一个分支**（`github.com` 的 git 协议可达）。

**推荐做法（只送小文件，大二进制继续留在 Release）**——在装有这两个 zip 的机器上执行：

```bash
git clone https://github.com/sunccchengze/FENGDIAN_2026.git
cd FENGDIAN_2026
git checkout -b intake/2026-10-22
mkdir -p _intake/delivery _intake/pinn
unzip "三机优化控制与中期答辩交付_20261022.zip" -d _intake/delivery
unzip "PINNs_multi_turbine_wake_simulation-outputchange(1).zip" -d _intake/pinn
# 大二进制（>50 MiB）已经在 Release 上，不要再进 git
find _intake -type f -size +50M -print -delete
git add _intake
git commit -m "intake: 2026-10-22 交付（仅 ≤50 MiB 文件；大二进制在 Release intake-2026-10-22）"
git push -u origin intake/2026-10-22
# 顺便把原包指纹发我（三行文本）：
sha256sum *.zip
```

**为什么不让整包进 git**：614.8 MB 单文件超 GitHub 100 MB 硬限；拆卷能绕过，但等于把 778 MB 永久写进每个 clone——
正是 [`ADR-2026-003`](../decisions/ADR-2026-003-大交付包存储口径.md) 2026-10-22 刚刚收紧掉的做法（存量 1.01 GiB 已认了，不再增加）。

**备选（不装 git）**：在 GitHub 网页上新建分支 `intake/2026-10-22` → "Add file → Upload files" → 拖入**解压后的文件夹**（不含 >50 MB 的文件）。
网页单文件上限 100 MB，所以大权重拖不上去，正好符合口径。
