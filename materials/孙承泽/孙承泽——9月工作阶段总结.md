# 二、项目立项与第一阶段（2026 年 3—6 月）

## 2.1 立项：我的模块使命从哪来

2026 年 3 月，团队完成国家重点领域项目《融合数据-物理驱动的风电流场智能感知与智能调控研究》申报并获立。项目围绕风电场偏航优化展开，技术路线为：CFD 大涡模拟 → POD + 多尺度 PINN 数字风场 → 气动代理模型（10—50ms 推理）→ PPO 单机功率跟踪 → MADDPG 多机协同 → 数字孪生平台 + 3×3 微缩风洞虚实闭环。

申请书中有两段原文，直接定义了本模块的使命：

* **其一：**申请书自陈短板："工业级可视化交互界面开发相关的 Node.js 前端开发环境配置、VSCode 编程技术应用上存在一定欠缺"，并做出对应承诺："每两月一轮算法性能测试与优化，同步进行可视化界面开发、数据传输协议适配的专项技术学习与开发实践"——本模块即该承诺的承担人；
* **其二：**申请书两处法定交付：研究内容③"构建一个风电场的线上运维系统，通过输入目前所需求的功率，系统能够实时输出并调整各个风机的偏航角，使整个风电场达到运作的最佳状态，实现风电场的智能运维"；阶段五预期成果"多机协同智能功率控制与数字孪生演示平台 1 套"及《虚实闭环验证报告》——两处交付的终点形态，即本模块最终要交出的东西。

## 2.2 第一阶段（2026 年 4—6 月）

第一阶段团队主线完成 CFD 算例矩阵（OpenFOAM 大涡模拟预研），为后续降阶模型、代理模型与优化控制奠定数据基础。本人早期进入项目，承担可视化线预研：调研顶级数字孪生界面形态、完成 3D Web 技术选型准备，7 月底正式开工，开始搭建项目可视化体系。

## 3.1 平台建成：15 页科研台

* **节奏：**7 月底开工：从封面与主控面板起步，随后整体重构为 15 页多页面科研站点；

* **演示性：**页面按"上动下静"组织：动态流场与交互控制置顶直接可见，静态出版图件沉底，便于组会与答辩现场演示。

## 3.4 科研诚信规范（本人建立并执行）

针对"科研数据上大屏容易失真"的风险，为平台确立了六条红线并全程执行：

* **红线一：**FLORIS 是数值模拟，全站任何角落不写成"现场实测"；
* **红线二：**尾流的艺术化包络 / 光流 / 粒子属结构策略示意，不冒充 CFD 等值面；只有读取真实数值场值的切片染色层才可标数据色标；
* **红线三：**浏览器端功率反求 = 双线性代理搜索，不写成浏览器端 PPO 推理；PPO 仅声明固定种子 × 200 回合离线评测；
* **红线四：**全站不生成任何无来源的功率、速度场、经济收益、种子稳定性结论；
* **红线五：**三级证据角标体系：【示意】/【代理】/【模拟】，所有动态读数默认挂标，关于页全文列明边界；
* **红线六：**可信数字只取封板文档钦定表（8095.15 / 10041.46 kW、+24.04%、97.97%、0.523% 等），设计稿中的占位数字实装时全部替换为真值。

并执行全站数字诚信审计（A—H 八类逐项落地）：POD 口径订正、转子平均值订正、风玫瑰页以真实数据重做、求解器表实测化、PPO / 机器学习结果加来源注记等。

8 月 19 日平台封板 v1.3：封板条款与交接说明作为法定边界，"平台封板、数据与口径不封板"。自此，项目所有科研数字有了唯一、可查、不可被随意改动的出处——这是后续数字孪生平台一切工作的地基。

# 四、数字孪生旗舰（8 月底 — 今）

平台代号 AEOLUS TWIN。一句话定位：申请书法定交付物"多机协同智能功率控制与数字孪生演示平台"的浏览器端演示形态——影院级、深色系、3D Web 数字孪生，对标顶级数字孪生大屏的观感；与科研平台的关系是"姊妹篇"：只复用其数据契约与研究成果，不复用页面代码。

## 4.1 立项：先审计申请书，再动手

动手前先把申请书终版逐字对表，形成一致性审计报告，得出三条决定性结论，定下全部工作口径：

* **结论一：**数字孪生不是"超额项"，而是申请书白纸黑字的结题法定交付物（研究内容③ + 阶段五）——定位为"结题刚需（法定）+ 质感超额（自律）"；
* **结论二：**申请书自陈短板（可视化 / 数据传输协议）即本模块法定使命；"真实数据接入"由可选外挂升级为阶段五必修接口（WebSocket 数据协议）；
* **结论三：**版本路线与申请书六阶段一一咬合：v0 支撑阶段二收官（组会演示 / 报告插图）→ v1 接阶段三 LES / PINN 真值、截图进软著①申请材料 → v2 回放 MADDPG 策略、图件进论文初稿 → v3 = 阶段五法定验收形态（接微缩风洞测控、虚实并排闭环）。

## 4.2 方案与选型（全部实测验证，无纸面推导）

* **调研：**18 组深度检索《顶级数字孪生界面调研报告》：顶级大屏三大流派、平台格局（51World / 数字冰雹 / Omniverse 等）、风电专项场景拆解，附参考图录；
* **选型：**3D 渲染栈（three.js WebGL + React + TypeScript + 后处理）、实时流式图表 / 静态图表分离、状态管理、相机控制等关键依赖逐项实测可构建、版本逐一核验；
* **部署：**部署方案锁定 Cloudflare Pages（硬约束登记：单文件 ≤ 25 MiB、文件数上限等），沿用"默认零后端"原则：所有资产本地化、完全离线可演示，真实遥测为可选外挂、默认关闭；
* **资产：**风机模型资产调研与自研决策：NREL 5MW 参数化自研（18 站位 / 塔筒放样 / 机舱几何），不采用外部模型，保证比例精确、口径可控；
* **美学：**视觉设计系统定稿（冰青版）：单一青色令牌、纯白线稿全息风机、1px 发丝线、克制不惹眼、不引入新色相，以用户钦定原图为视觉真值。

## 4.3 平台建成什么（v0 形态）

1920×1080 等比大屏舞台：深空蓝背景 + 纯白全息线稿；34 秒开场无人机运镜（惯性运镜、任意时刻可跳过）+ 13 个预设机位。

* **世界场景：**真实海洋：多方向波叠加 + 菲涅尔反射 + 日月镜面高光 + 波峰泡沫 + 深度配色——白天湛蓝波涛汹涌，夜间漆黑如墨暗潮涌动；海盆内九机阵列、海岸陡升、开放外海；
* 海岸与远景：岸距场、拍岸碎浪、地平线收边、实例化远岸森林（4800 株）；程序化星野 / 极光 / 白昼卷云、日月视差、日照金山；昼夜光影连续（含午夜零点交界修复）；
* **主体：**九台风机：NREL 5MW 参数化几何，纯白线稿（菲涅尔壳 + 边缘线 + 手工肋线），任何角度不变暗变灰；基座能量环、集电电缆亮度视角无关；
* 场元素：九条放射状集电电缆（等宽线 + 电流脉冲）、风况粒子（11 条列向来流 + 6 条远脊来流，与功率模型风向同源）、玻璃升压站、地面星芒；
* 声场与环境：WebAudio 合成海面 / 风声场（与浪高同源）；草地及分档剔除（低画质档零渲染）。

## 4.4 HUD 控制台与闭环控制（研究内容③的验收点）

* **数据契约：**全场状态由唯一纯函数真值源输出，KPI / 九机功率矩阵 / 风况雷达 / 实时功率曲线 / 告警 / 3D 场景读同一个对象——"联动即同一帧"，不存在界面与 3D 对不上的问题；
* **闭环演示：**输入需求功率（4—45 MW）→ 系统实时输出限电反馈与各机运行状态；一键寻优 → 实时输出九机最优偏航角（代理模型口径，一键寻优功率增益实测 +36.9%，界面明示【代理】角标）；
* **风况雷达：**400 / 800 m 距离环、九机功率光点、Jensen 尾流走廊（与 3D 粒子场 / 功率引擎同公式）、来流矢量；
* **时间轴：**真实 50 s = 模拟 24 h，可暂停、可任意拖动 = 任意时刻确定性回放；
* **物理内核：**浏览器端 Jensen 尾流代理（对 FLORIS 离线实算定标，复合误差 2.07%）+ NREL 5MW 功率曲线锚点；物理内核（GCH 尾流模型 + 全场评估）已建成——无偏航功率链已与 FLORIS 真值闭环校验（47 个校验点、误差 ≤ 0.05 kW），偏航偏折链仍在收口（见 7.2 遗留项）；
* **遥测接入：**默认演示源；WebSocket 数据传输协议骨架已就位，可对接真实 SCADA / 算法输出，断线自动回退演示源——即阶段五"虚实闭环"的必修接口。

## 4.5 数据诚信口径（继承并升级）

继承科研平台六条红线，升级为界面可见的四级证据角标：【示意】（几何 / 构图示意，如程序地形、3×3 布置）/【代理】（浏览器端代理模型推算，如尾流损失、一键寻优）/【模拟】（FLORIS 数值模拟真值）/真实（离线实算引用，只出现在文档与报告，不与演示数字混写）。页脚固定声明"浏览器端演示数据 · 非 SCADA/FLORIS 实时值"；全部可信数字只取科研平台钦定表，文档、说明、界面角标三处一致。

# 五、两套平台的关系：一条证据链、两种形态

两个仓库、两套平台在本项目中处于同等权重：前者封存"已验证的证据"，后者迭代"将被验收的形态"。它们的分工与继承关系如下。

# 六、现状、遗留项与下一步计划

## 6.1 现状总览

* 项目主线：阶段二（LES 数据库 200+ 工况 + POD 报告）收官中，阶段三（代理 PINN + PPO、软著①）启动；

* 数字孪生：v0 已交付——世界场景 / 九机线稿 / HUD 闭环 / 质量四闸常绿 / 画质三档 / 离线可用，满足"阶段二报告插图 + 组会现场演示"需求，持续细化中。

## 6.2 遗留项（如实列出）

* **偏航物理内核：**GCH 物理内核已建成，无偏航链已与 FLORIS 真值完全闭环校验；偏航偏折 / 二次导向链仍有偏差（下游单机功率偏差约 24.6 kW 量级、全场统一偏航偏差约 73 kW 量级、上游排扫描偏差更大），需继续收口——本模块下阶段第一优先级；
* **真实数据接入：**阶段二 LES 数据库（200+ 工况，预计 GB 级时空快照）的交接契约待团队定稿；孪生 v1 换接预案已备好（稳态切片 → 时空场快照的契约扩展位已预留，架构不返工）；数据量超出 Pages 单文件约束，本地数据包双轨预案已就绪；
* **实机验收：**当前质量数字在软件渲染环境实测，帧率与首屏时间需实机 GPU 终验。

# 七、总结与自评

六个月来，本模块完成了三步交付：从申请书承诺，到在线科研证据中心（已封板），到影院级数字孪生 v0（迭代中）。两套平台一条证据链、两种形态，数据同源、口径全局唯一。

最大的经验：先"把申请书逐字对表"，再动手建东西——法定交付物在前、质感超额在后；先把证据封死（科研平台），再让验收形态迭代（孪生平台）；两个平台之间靠"数据契约 / 红线 / 钦定数字 / 技能库"四类资产继承，使新平台 90% 的口径直接承继、不重头再来。

最大的短板：偏航物理内核尚未完全闭环、真实数据尚未换接、实机 GPU 验收尚未完成——三者均已列入下阶段第一优先级。

自始至终执行"准确、不是好看"的口径：平台上的每个数字都来自实测，每条数据都有来源标注，不使用"可以直接答辩"一类表述，所有结论附实测证据。
