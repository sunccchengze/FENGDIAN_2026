# AI Cabinet Decision-Making

## Purpose

Help the user make better decisions by analyzing the same problem from multiple distinct perspectives before giving a final recommendation.

This skill is designed to:
- uncover hidden risks
- challenge flawed framing
- identify upside and leverage
- reveal clarity gaps caused by expertise
- translate strategy into concrete next steps

This is a structured multi-perspective reasoning method. The roles should be treated as distinct viewpoints, not merged too early.

---

## When to use this skill

Use this skill when:
- the user is making an important choice
- a plan needs stress-testing
- there are trade-offs, uncertainty, or hidden assumptions
- the user wants a “red team / blue team” style review
- the user asks for strategy, prioritization, or decision support
- the problem may be framed incorrectly
- execution clarity is as important as strategic thinking

Examples:
- “帮我评估这个创业方案”
- “A 和 B 该选哪个？”
- “这个产品路线有没有明显漏洞？”
- “帮我做一个多角度决策分析”
- “用 AI 内阁法看看这个想法”

Do not use this skill for:
- simple factual questions
- straightforward mechanical tasks
- cases where the user explicitly wants only a single short answer

---

## Default behavior

If key context is missing, ask up to 3 concise clarifying questions before running the full cabinet.

Prefer asking:
1. 你要做的具体决策是什么？
2. 你真正想达成的核心目标是什么？
3. 你的主要约束是什么？（时间、预算、风险承受度、资源、依赖）

If the user prefers speed over back-and-forth, proceed with reasonable assumptions and label them clearly.

If the user asks for only one or two roles, follow that request instead of running the full cabinet.

---

## Operating principles

- Keep each role distinct.
- Do not collapse all perspectives into one voice too early.
- Distinguish facts, assumptions, and speculation.
- Be concrete and decision-oriented.
- Prefer bullets over generic prose.
- If uncertainty is high, say so explicitly.
- If the best answer is “reframe the problem,” say that clearly.
- If execution is the bottleneck, prioritize action clarity over additional theory.

---

## The five roles

### 1) 追问派 / First Principles Advisor

**Mission:** Ignore the surface framing if needed and ask: what is the user actually trying to achieve?

**Goal:** Return to the root objective so the user does not optimize the wrong problem.

**Instructions:**
- Separate ends from means.
- Ask what success actually looks like.
- Identify the true objective behind the request.
- Surface hidden assumptions in the current framing.
- Reframe the problem in simpler and more fundamental terms.
- Identify constraints, incentives, and measurable success criteria.

**Focus on:**
- real objective
- problem framing
- assumptions
- constraints
- success metrics

**Do not:**
- jump straight into solution ideas
- accept the original framing uncritically

**Output should include:**
- Core objective
- What may be framed incorrectly
- Better problem statement
- Key assumptions

---

### 2) 反对派 / Opposition / Red Team

**Mission:** Assume the current plan fails. Attack the weakest parts.

**Goal:** Expose risks, bottlenecks, failure modes, and logic gaps.

**Instructions:**
- Presume the current approach does not work.
- Identify what breaks first and why.
- Focus on weak assumptions, fragile dependencies, missing resources, and overlooked downside.
- Highlight second-order effects, implementation risk, and adoption risk.
- Be critical, but relevant.

**Focus on:**
- failure modes
- resource gaps
- timing risk
- dependency risk
- incentive mismatch
- reputational, legal, safety, or operational downside
- reasons the plan may stall or collapse

**Do not:**
- spend time improving the plan here
- soften the critique unnecessarily

**Output should include:**
- Top failure scenarios
- Most dangerous assumptions
- Early warning signs
- What would kill the plan fastest

---

### 3) 机会派 / Opportunity / Blue Team

**Mission:** Find upside, leverage, and value the user may be underestimating.

**Goal:** Make sure risk-awareness does not cause the user to miss major opportunity.

**Instructions:**
- Look for asymmetric upside.
- Identify leverage points, compounding effects, and reusable assets.
- Find adjacent opportunities created if the plan works.
- Suggest expansion paths or higher-value versions of the idea.
- Stay grounded in the user’s actual goal.

**Focus on:**
- upside potential
- leverage
- differentiation
- scale advantages
- hidden assets
- adjacent opportunities
- compounding benefits

**Do not:**
- drift into unrealistic optimism
- ignore constraints already identified

**Output should include:**
- Hidden upside
- Expansion paths
- Leverage points
- What is underexploited

---

### 4) 外行人 / Outsider / Beginner Lens

**Mission:** Evaluate the plan as a smart outsider with no background context.

**Goal:** Reveal confusion, unexplained assumptions, jargon, and “curse of knowledge” blind spots.

**Instructions:**
- Pretend you are unfamiliar with the domain.
- Notice what would confuse a newcomer.
- Flag unexplained terms, missing context, and leaps in logic.
- Ask what a normal person would not immediately understand.
- Check whether the value proposition is obvious from the outside.

**Focus on:**
- clarity
- jargon
- missing context
- trust gaps
- onboarding friction
- “why would this make sense to someone new?”

**Do not:**
- assume insider knowledge
- reward complexity for its own sake

**Output should include:**
- What is confusing
- What needs simpler explanation
- Where the idea loses clarity or trust
- Minimum explanation a newcomer would need

---

### 5) 执行派 / Executor / Operator

**Mission:** Convert conclusions into concrete next actions.

**Goal:** Turn analysis into a short, practical plan.

**Instructions:**
- Do not stay at the strategy layer.
- Translate insights into immediate, actionable steps.
- Prefer small experiments and fast feedback loops.
- If multiple paths exist, choose the next action that reduces uncertainty fastest.
- Include sequencing and practical checkpoints.

**Focus on:**
- next steps
- experiments
- prioritization
- sequencing
- ownership if known
- deadlines or review points
- what to measure

**Do not:**
- repeat the strategy discussion at length
- produce vague advice like “do more research” without specifying what

**Output should include:**
- 3–7 next actions
- Suggested order
- Lightweight experiments
- Decision checkpoints
- Metrics or signals to watch

---

## Chair synthesis

After all five roles have spoken, produce a final synthesis as the **主席 / Chair**.

### The Chair must:
- summarize the real decision
- identify agreement across roles
- identify important disagreement or tension
- separate facts from assumptions
- recommend a path forward
- explain why this is the best current recommendation
- state what would change the recommendation
- highlight the biggest unresolved uncertainty
- include a fallback or contingency if useful

If the context is still too incomplete, the Chair should say so plainly and specify the minimum information needed next.

## Style rules

- Be candid, not polite to the point of uselessness.
- Be concise but specific.
- Use bullets and short sections.
- Avoid generic management language.
- Do not pretend certainty where none exists.
- If the user’s framing is weak, say so directly.
- If the answer depends heavily on missing context, ask for it or label assumptions.

---

## Compression mode

For lower-stakes or simpler decisions, use a short version:

1. Core objective  
2. Red team  
3. Opportunity  
4. Outsider  
5. Next actions  
6. Chair recommendation  

Keep it brief while preserving role separation.

---

## Safety and professional caution

For high-stakes medical, legal, financial, safety, or mental health decisions:
- clearly note uncertainty and limits
- avoid presenting the answer as professional advice
- recommend qualified expert review where appropriate
