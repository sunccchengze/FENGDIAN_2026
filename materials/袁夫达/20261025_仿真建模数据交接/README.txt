三、三版数据的演进（一句话版）
--------------------------------------------------
v1  先把链路跑通：三机统一控制。暴露三个问题——单机曲线偏低 4.6%、
    控制维度不够、深尾流样本最少。
v2  针对性改三处：Cp 按官方曲线标定（k=1.0347）、改为逐机控制、
    正对来流加密风向。误差降到 25.4 kW，但埋下隐患——每个风速只挑 3 个
    控制模式，导致桨距与风速共线。
v3  响应扫描发现桨距效应学不到（偏差 433%），于是把桨距与风速解耦：
    每个风速下所有可行的桨距档全部纳入。桨距响应偏差降到 1.15%，
    偏航降到 2.14%。

三版不是替代关系，而是每一版都在回答上一版暴露的问题。

四、核心指标速查
--------------------------------------------------
数据规模         20,160 行 × 18 列（12 输入 / 6 输出）
训练/验证/测试   12,096 / 4,032 / 4,032
功率自洽性       由 (Ueff, λ, β, γ) 独立复算，中位偏差 0.000%
单机曲线对标     额定以下与官方 NREL 5MW 表偏差 −1.24% ~ +1.24%
阵列效率         47.9% ~ 98.4%（正对来流约 48%）
留出集误差       平均 50.9 kW = 额定功率的 1.02% = 平均功率的 4.70%
关键响应校验     风向 1.98% | 风速 8.26% | 偏航 2.14% | 桨距 1.15%

--------------------------------------------------
五、怎么重跑
--------------------------------------------------
两个环境（生成只需 FLORIS，训练与响应校验需要 TensorFlow）：

A. 生成环境（FLORIS 4.6.6 + numpy/pandas/matplotlib）
   cd scripts
   python build_table.py                        # 建表 + 标定，约 3 秒
   python generate_cases.py --ws-step 1.0       # 生成 v3，约 3 分钟
   python validate_cases.py                     # 15 条判据 + 出图
   python versions\gen_legacy.py v1             # 重新生成 v1，约 2 分钟
   python versions\gen_legacy.py v2             # 重新生成 v2，约 2 分钟

B. 训练 / 分析环境（TensorFlow 2.16.1 + tf-keras 2.16.0）
   python analyze_training.py                   # 需 PINN 项目在同级目录
   python response_check.py predict             # 需先跑 truth 模式生成真值

注意：analyze_training.py、check_pinn_interface.py、response_check.py 的
predict 模式依赖 PINN 项目（要 import modify_pinn_wind_io 加载模型）。
其余脚本自包含，可单独拷走。

--------------------------------------------------
六、必须转告下游的三条限制
--------------------------------------------------
1. 负输出：读出层是线性的，无物理约束，测试集出现 445 个负值（1.8%），
   集中在 8~50 kW 的近停机降载工况。优化程序接入前必须做 P = max(P, 0)。

2. 不可外推：有效范围 风速 5~12 m/s、偏航 |γ| ≤ 20°、桨距 0~14°、
   三机 3 倍直径链式、NREL 5MW。超出即外推，不作保证。

3. 标签源是解析模型：数据由 FLORIS 生成（单机气动已按官方曲线标定，
   偏差 ≤1.3%），但尾流叠加部分尚无 CFD 或实测对标。
   本模型是「FLORIS 的代理」，不是「物理真值」。优化给出的最终方案
   仍应经 FLORIS 复核；有条件时用 Fluent 算例交叉验证。
