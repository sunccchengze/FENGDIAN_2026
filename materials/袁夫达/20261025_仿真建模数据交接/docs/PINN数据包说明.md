# pinn_wind_data —— PINN 新版 12 输入 / 6 输出训练数据生成包

本目录为 `PINNs_multi_turbine_wake_simulation-outputchange` 的新版接口
（三风况量 + 九控制量 → 三机功率 + 三机有效风速）生成可训练数据，
并附一套带数值阈值的合理性论证。

## 一、三分钟复现

```powershell
cd <项目根目录>

# 1. 从 FLORIS 自带的 (λ, β) 曲面构造多维功率/推力表
.\.venv\Scripts\python.exe pinn_wind_data\build_table.py

# 2. 批量仿真生成数据（约 50 秒）
.\.venv\Scripts\python.exe pinn_wind_data\generate_cases.py

# 3. 数据合理性论证（15 条判据 + 9 张图）
.\.venv\Scripts\python.exe pinn_wind_data\validate_cases.py

# 4. 用 PINN 脚本自己的读取函数验收
.\.venv\Scripts\python.exe pinn_wind_data\check_pinn_interface.py
```

## 三、方法：三块拼图

| 块 | 内容 |
|---|---|
| 物理数据 | FLORIS 自带的 NREL 5MW `(叶尖速比 λ, 桨距 β) → Cp/Ct` 曲面（29×36 网格，λ 3–10、β −5°~30°） |
| 耦合方式 | 把曲面折叠进 FLORIS 的 `multi_dimensional_cp_ct` 机制：条件维 = (桨距, 叶尖速比) |
| 自洽来源 | 每个 (λ, β) 块里 **Ct 是常数、P ∝ U³**，功率与尾流用的是同一个气动点 |

**为什么这样就自洽**：表里 λ 固定，等于声明"控制器把叶尖速比稳住"。
于是每台机自己的转速 `ω_i = λ · Ueff_i / R` 由当地盘面风速决定，
查到的 Cp/Ct 恰好是 (λ, β) 那一格的常数——**不需要外层迭代**，
运行时的功率、推力、转速天然闭环。

## 四、关键设计决策（答辩时会被问到的四件事）

| 决策 | 取值 | 理由 |
|---|---|---|
| 控制指令 | **全场统一**（同一 λ 目标、同一桨距） | 代表"场级降载/限速指令"；实际转速因 Ueff 不同而**逐机不同**（`ω_i = λ·Ueff_i/R`） |
| 桨距/速比网格 | 桨距 0–14° 步长 2°（8 档）× 速比 6/7/8（3 档，9 不可行） | FLORIS 多维表是**最近邻**选择，控制量必须落在网格点上 |
| 运行点挑选 | 每条风速取 4 个：λ=8 最优跟踪 / λ=7 偏速 / λ=6 低速 / 在 λ=8 上取中等偏深桨距 | 让 λ 与桨距都有真实变化，避免训练脚本报"控制量恒定" |
| 功率算法 | FLORIS 只给流场；功率由 **128 点盘面积分**自己算 | FLORIS 4.6 硬限制 `turbine_grid_points ≤ 3`（9 个点），深尾流下会把 P2/P3 次序算反 |
| 功率口径 | 电功率，η=0.944 | 与 `nrel_5MW.yaml` 注释一致，也与项目早期 2448 条数据集同口径 |
| 风速下限 | 5 m/s（不取 4） | 3–5 m/s 是切入过渡区，本表未建模 Cp 爬坡；4 m/s 会比官方曲线高 20% |
| 坐标口径 | 默认 `scaled`：乘 `30.1/125.88 = 0.2391` | 冻结主干的坐标归一化按原域尺度（R=15.05 m）写死；缩比后几何比例与真实完全一致，只是绝对尺度不同 |

## 八、已知局限（必须在报告里写明）

1. **标签是"FLORIS 的代理"**：解析尾流模型产物，不是真实流场也不是 CFD 结果。
   能证明映射自洽、链路可用；不能证明物理绝对正确。
2. **Cp/Ct 曲面是 FLORIS 自带的 demo 数据**（源码有明确告警），与官方 NREL 5MW 表差 −2.1%~−4.6%。
3. **统一指令**：三台机同桨距；真实风场是逐机独立变桨。
4. **准静态**：无尾流传播延迟、无湍流时间序列。
5. **不覆盖切入区（<5 m/s）与切出区**，不外推到其他布局/机型。
6. **9 维控制量的 6 维来自一张经验曲面**：桨距/转速的物理依据是 Cp/Ct 曲面，不是逐台 BEM 计算。

## 十、v2 升级（当前数据版本）

在 v1（15 264 行、统一控制、未经标定的 demo 曲面）基础上做了三处实质改进。

### 1. Cp 曲面按官方功率曲线标定

`build_table.py` 先用孤立单机在 8 m/s 下对比 FLORIS 官方 `nrel_5MW` 表与本表，得到标定因子：

```
k = 1.0347     1.6952 MW -> 1.7540 MW（官方 1.7540 MW）
标定残差 +0.000%
```

Ct **未标定**：实测 λ=8/β=0 处 demo Ct=0.7878，官方表 8 m/s 处 0.7871，差 0.09%，可忽略。

效果：额定以下单机曲线与官方的偏差从 **−4.55%~−2.15% 收紧到 −1.24%~+1.24%**（判据 C14）。

### 2. 逐机控制（不再是"三台机同一个桨距"）

控制模式表（每台机一个 `(桨距°, 叶尖速比)`）：

| 模式 | T1 | T2 | T3 | 用途 |
|---|---|---|---|---|
| `optimal_l8` | (0, 8) | (0, 8) | (0, 8) | 三机最优跟踪 |
| `derate_l8` | (6, 8) | (6, 8) | (6, 8) | 统一降载 |
| `stagger_mix` | (10, 8) | (0, 7) | (4, 8) | **逐机错列 + 混合速比** |
| `high_l6` | (8, 6) | (8, 6) | (8, 6) | 高风速降速运行 |
| `stagger_l6` | (12, 6) | (4, 6) | (8, 6) | 高风速下的逐机错列 |

实现方式：按 `(风向, 三机块组合)` 分组，每组用 `fmodel.set(turbine_type=[t1,t2,t3])`
挂三张独立的功率/推力表，因此 `pitch1/2/3`、`rotor_speed1/2/3` 是逐机不同的真实运行点。

每个风速只保留物理可行的模式（转速不超额定、每台机功率不超 5 MW），且每个风速最多取 3 个，
这样 5–9.5 m/s 拿到 3 种控制、10–12 m/s 自动切到 λ=6 的两种。

### 3. 正对来流加密

风向网格 = 15° 网格 + 额外插入 **85 / 95 / 265 / 275°**，共 28 个方向。
原因：留出误差在正对来流处是其它风向的 2.8 倍（7.1% vs 2.5%），那里需要更多样本。

### v2 训练结果（187 轮，早停触发）

| 输出 | v1（15 264 行） | v2（13 440 行） |
|---|---|---|
| P1 MAE | 25.4 kW | **20.0 kW** |
| P2 MAE | 30.0 kW | **29.0 kW** |
| P3 MAE | 34.8 kW | **27.3 kW** |
| 平均 | 30.1 kW | **25.4 kW（−15.5%）** |
| Ueff 平均 MAE | 0.035 m/s | 0.043 m/s |
| 负输出 | 0 | **35** |

**P3（下游机）改善最大：34.8 → 27.3 kW**，这正是"正对来流加密"直接命中的地方。

两条必须一起讲的 caveat：

1. **MAPE 反而从 2.87% 升到 5.01%，不能当成变差**。v2 新增了逐机降载工况，最低功率到 10.7 kW，
   相对误差的分母被大幅缩小。**MAE（绝对 kW）才是可比的**，它降了 15.5%。
2. **负输出从 0 变成 35 个**。控制范围一宽，线性读出层的非负缺陷就暴露了。
   → 下游优化必须先做 `max(P, 0)`，或把读出层改成 `softplus`。

### 坐标口径的四点扫描（这是本轮最重要的实验结论）

同一份 v1 数据、同一 seed、只改坐标缩放 s：

| s | 主干以为的机间距 | 功率 MAE | 结论 |
|---|---|---|---|
| 0.120 | 1.5 D | 36.0 kW | 太小，三机几何被压在一起 |
| **0.239** | **3.0 D（真实）** | **30.1 kW** | **最优，且是唯一物理正确的编码** |
| 0.558 | 7.0 D | 56.8 kW | 假装 7D，尾流重叠被低估 |
| 1.000 | 12.6 D | 79.6 kW | 假装 12.6D，第三台机还越出归一化框 19.5% |

**U 形，最小值精确落在物理正确的那一点。** 机制已用冻结主干的特征验证：
s=0.239 时三台机特征范数是分布内参照的 0.77–0.93 倍且互相可分（cos(T2,T3)=0.91）；
s=0.558 时 T3 的特征范数塌到 0.41、cos(T2,T3)=0.38（几乎正交，读出层学不动）；
s=1.0 时 cos(T1,T2)=0.52。

### 本轮的操作失误（如实记录）

v2 重新生成时**覆盖了 v1 的 `cases_wind.csv`**，导致 v1 模型无法在新数据上复评。
v1 的数字只能引用其 `training_report.json` 里的记录。后续应给数据文件加版本后缀。

### 与之配套的判据调整（v2）

旧判据 `P1≥P2≥P3`、`横风三机相等` 只在"三机同控制"时成立；本版允许逐机不同桨距，
上游机被主动降载时 `P1<P3` 是合理物理现象。因此这两条判据改为**只在统一控制子集上校验**，
另把阵列效率的分母改成逐机用自己的 (λ, β) 计算。判据没放宽，只是对准了新的数据结构。

## 十一、v3：修掉「桨距与风速共线」的缺陷（当前数据版本）

### 怎么发现的

留出集 MAE 25.4 kW（0.5% 额定）看起来完全正常，**但响应校验把它戳穿了**：
固定 8 m/s 扫集体桨距 0→10°，FLORIS 真值从 2.55 MW 掉到 **0.46 MW**，
而 PINN 给出一条几乎平的线（2.51 → 2.35 → 2.48），最大偏差 **433%**。

| 扫的变量 | 平均偏差 | 最大 | 判定 |
|---|---|---|---|
| 风向 θ∞ | 0.77% | 2.29% | ✅ |
| 入口风速 U∞ | 4.11% | 10.59% | ⚠️ 11–12 m/s 偏低 |
| 偏航 γ1 | 6.98% | 22.20% | ⚠️ 仅 ±20° 内可信 |
| **集体桨距 β** | **84.04%** | **433.65%** | ❌ 完全没学到 |

### 根因（是数据设计的问题，不是模型的问题）

v2 按"每个风速挑 3 个控制模式"，而 `λ=8` 在 10 m/s 以上会超额定转速被排除，
结果 **β>0 只出现在高风速、β=0 只出现在低风速** —— 桨距与风速几乎完全共线。
模型无法把两者分离，遇到"8 m/s + 桨距 10°"这种组合（训练集里不存在）就乱猜。

### 修法

每个风速下，把**所有物理可行的桨距档**都纳入（按转速上限自动降 λ），
均匀取 4 档 + 2 个逐机错列；偏航加密到 `0 / ±10 / +20` 与错列。

v3 规模：**20 160 行**（8 风速 × 28 风向 × 3 TI × 5 偏航 × 6 控制设置），
用到 10 个控制块（v2 只有 8 个），15/15 判据通过。

### 这条经验值得写进中期材料

> **随机留出集误差无法发现"控制量失效"。**
> v2 的 25.4 kW 误差掩盖了 433% 的桨距响应错误——因为测试集里没有
> "低风速 + 大桨距"这种组合，模型在自己见过的分布里插值得很好。
> 只有**单变量响应扫描**（拿模型扫参数、和真值曲线逐点比）才能暴露它。
> 这也是为什么 `response_check.py` 应该成为每次换数据后的固定动作。

### v3 训练与验收结果

训练 200 轮（未早停），26 秒/轮，约 93 分钟。

| 输出 | MAE | RMSE |
|---|---|---|
| P1 | 40.9 kW | 63.5 kW |
| P2 | 55.0 kW | 77.3 kW |
| P3 | 56.7 kW | 73.9 kW→77.9 kW |
| 平均 | **50.9 kW** | — |

归一化：**= 额定功率的 1.02%**，**= 测试集平均功率（1082 kW）的 4.70%**。
MAPE 22.56% 不可用作判据——测试集功率跨三个数量级（9 kW ~ 4.76 MW），
中位数只有 424 kW，10% 的样本低于 52 kW，近停机工况会把相对误差拉到很高。

**响应校验（唯一能证明"控制效应学到了"的指标）：**

| 变量 | v2 | v3 | 变化 |
|---|---|---|---|
| **集体桨距 β** | 84.0% / 433.7% | **1.15% / 4.49%** | **修复** |
| **偏航 γ** | 6.98% / 22.20% | **2.14% / 4.49%** | 改善 3 倍 |
| 入口风速 U∞ | 4.11% / 10.59% | 8.26% / 14.86% | 变差（见下） |
| 风向 θ∞ | 0.77% / 2.29% | 1.98% / 17.84% | 均值仍 <2% |

**代价与原因**：为了把样本量控制在 20k，风速网格从 0.5 m/s 粗化到 1.0 m/s（15 档 → 8 档），
所以风速插值变差（4.1% → 8.3%）。这是明确的取舍，不是退化 bug。

**新出现的问题**：负输出从 35 个涨到 **445 个（占 1.8%）**。原因是数据里新增了大量
8–50 kW 的近停机降载工况，线性读出层在这些点上会给出负值。**优化侧接入前必须钳制。**

### 下一步建议（按优先级）

1. **风速网格回到 0.5 m/s**：把 8 档改回 12–15 档，用减少偏航档位（5→4）换样本量，
   规模仍在 20k 左右，可把风速插值从 8.3% 拉回 4% 量级。
2. **给功率设下限**（例如 P ≥ 100 kW 才入样），消掉近停机工况与负输出。
3. 读出层改 `softplus`，从结构上保证非负。

### 误差归因（图 `fig12`、`fig13`）

| 分档 | 功率平均相对误差 | 说明 |
|---|---|---|
| 其它风向 | 2.54% | 尾流部分遮挡/错开 |
