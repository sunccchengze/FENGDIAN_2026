PINN 代理模型（v3）训练成果包 —— 使用与复现说明
================================================================
生成日期：2026-10-25
打包人：建模与仿真（袁夫达）
用途：把「三台风机的风况 + 控制量」映射到「三机功率 + 三机盘面有效风速」
      的代理模型，附完整的数据生成脚本，可从头复现。

二、数据一共有几版（三版全部可逐字节复现）
----------------------------------------------------------------
PINN 的 12 输入接口一共做过 3 版数据，本包**三版都收**，且都能逐字节复现：

| 版本 | 样本数 | 关键改动 | SHA256（前 16 位） | 复现 |
|---|---|---|---|---|
| v1 | 15,264 | 三机统一控制、Cp 未标定 | cf2dfeae34a015a4 | ✓ |
| v2 | 13,440 | Cp 标定、逐机控制、加密风向 | a22b833e4fcfa57e | ✓ |
| v3 | 20,160 | 桨距与风速解耦（修 v2 缺陷） | 5e2e96182342eee4 | ✓ |

文件位置：
  data\cases_wind.csv              = v3（主交付数据）
  data\versions\cases_wind_v1.csv  = v1
  data\versions\cases_wind_v2.csv  = v2
  data\versions\version_manifest.json  三版的哈希、改动说明、复现要点

复现方式（生成环境，FLORIS 4.6.6）：
  python scripts\versions\gen_legacy.py v1      # 约 2 分钟
  python scripts\versions\gen_legacy.py v2      # 约 2 分钟
  python scripts\generate_cases.py --ws-step 1.0   # v3，约 3 分钟

脚本会自己算 SHA256 并与训练报告里记录的值比对，打印「逐字节一致 ✓」。

**复现时踩过的三个坑（已写进脚本注释，也是探索过程的记录）：**
1. v1 走多维表 CSV 中转，功率/推力系数按 %.6f 取整到 6 位小数后才喂给 FLORIS；
   v2 改为内存里直接传全精度数组。这一处差异会让 Ueff 从第 7 位起变化，
   进而体现在 CSV 的 6 位小数上——不按各自路径构造就对不上。
2. v1 的涡轮机 yaml 里 TSR 固定为 8.0（它只参与 GCH 的尾流旋转涡量项），
   而 v2 起 TSR 取该块的叶尖速比。这个标量会改变 Ueff，必须区分。
3. v2 的 Cp 必须用 table_manifest_pinned.json 里记录的块值：
   manifest 里把标定因子写成了 6 位小数（1.0347），而当时实际乘的是未取整的 k，
   拿 npz 乘取整后的因子重算会有 1e-7 级偏差。

----------------------------------------------------------------
三、模型是什么
----------------------------------------------------------------
这是对 PINN 项目 OutputChange\wind_iochanged_9ms 那套「冻结主干 + 新增读出」
结构的训练成果：原 3,087,200 个主干参数全程冻结（训练后校验未变），
只训练了新增的 27,106 个参数。

输入（12 维，顺序严格固定）：
  ambient_wind_speed_m_s, ambient_wind_direction_rad, turbulence_intensity,
  yaw1, pitch1, rotor_speed1, yaw2, pitch2, rotor_speed2,
  yaw3, pitch3, rotor_speed3

输出（6 维）：
  P1, P2, P3           单位 W（电功率口径，η_gen = 0.944）
  Ueff1, Ueff2, Ueff3  单位 m/s（盘面 128 点等面积采样的轴向速度 cubic-mean）

单位约定：yaw / pitch 用弧度，rotor_speed 用 rad/s，TI 用 0~1 的小数。
风向是「风吹向」的方向：0 沿 +x，pi/2 沿 +y，从上往下看逆时针为正。
（由 FLORIS 的气象来向换算：theta_flow = (270 - wd_met) mod 360）

----------------------------------------------------------------
四、数据是怎么造的（逻辑闭环）
----------------------------------------------------------------
链条：风况 + 控制量 → FLORIS 解多机尾流场 → 每台机盘面 128 点等面积采样得
Ueff → 由同一张 Cp 表算功率 P = 0.5·ρ·A·Ueff³·Cp(λ,β)·η·cos^1.88(γ)
→ 由 ω = λ·Ueff/R 得各机转速。

闭环的含义：功率、转速、盘面风速三者互相锁定，任意一个都能由另外两个反推。
校验结果：由 (Ueff, λ, β, γ) 独立复算功率，与数据偏差 0.000%。

训练数据覆盖：
  · 风速 5~12 m/s（8 档）、风向 28 档（含 85/95/265/275 正对来流加密）、TI 三档
  · 每风速 6 组控制设置（4 个统一桨距 + 2 个逐机错列）、偏航 5 档（0/±10/+20/错列）
  · 桨距 0~14°、叶尖速比 6/7/8

五、精度与有效范围
----------------------------------------------------------------
留出集（4,032 行，模型未见过）误差：
  P1 40.9 kW  |  P2 55.0 kW  |  P3 56.7 kW
  平均 50.9 kW = 额定功率的 1.02% = 测试集平均功率的 4.70%
  Ueff 0.060 m/s

单变量响应校验（与 FLORIS 真值逐点比较，平均偏差）：
  风向 1.98%  |  入口风速 8.26%  |  偏航 2.14%  |  集体桨距 1.15%

有效范围：风速 5~12 m/s、偏航 |γ| ≤ 20°、桨距 0~14°、
三机 3 倍直径链式布局、NREL 5MW 机型。超出即外推，不作保证。

六、怎么用
----------------------------------------------------------------
必须使用训练同一环境：Python 3.12 + TensorFlow 2.16.1 + tf-keras 2.16.0

把本包解压到 PINN 项目下，然后：

    python modify_pinn_wind_io.py predict \
        --run "路径\本包解压后的目录" \
        --csv "prediction_example.csv" \
        --output "predictions.csv"

在优化程序内调用时，先 import 该脚本注册自定义层，再加载模型：

    import modify_pinn_wind_io as io
    tf, keras, *_ = io.tensorflow_components()
    config, positions = io.validate_config(Path("config_used.json"))
    model = keras.models.load_model("trained.keras", compile=False)
    out = model(io.inputs_for(raw_12d_array, positions), training=False).numpy()

注意：
  1. 同一进程内只加载一次模型；不要用旧版九输入模型。
  2. 预测时必须使用 config_used.json 里的机位，不要改全局配置。

----------------------------------------------------------------
七、怎么从头复现数据（两个环境）
----------------------------------------------------------------
数据生成只需要 FLORIS（CPU），训练与响应校验需要 TensorFlow。两个环境分开：

  A. 生成环境（FLORIS 4.6.6 + numpy/pandas/matplotlib）
     cd scripts
     python build_table.py                                   # 建表 + Cp 标定，约 3 秒
     python generate_cases.py --ws-step 1.0                   # 生成数据，约 3 分钟
     python validate_cases.py                                # 15 条判据 + 出图
     python check_pinn_interface.py                          # 需 PINN 项目在同级目录

  B. 训练 / 分析环境（TensorFlow 2.16.1 + tf-keras 2.16.0）
     python analyze_training.py                              # 需 PINN 项目在同级
     python response_check.py truth    （用 A 环境）
     python response_check.py predict  （用 B 环境）

build_table.py 会在 scripts\turbine\ 下重写多维表 CSV 与涡轮机 yaml，
并在 scripts\out\ 下重写 table_manifest.json；generate_cases.py 依赖后者。

----------------------------------------------------------------
八、三条必须注意的局限（务必转告优化同学）
----------------------------------------------------------------
1. 负输出问题
   读出层是线性的，无物理约束。测试集中出现 445 个负值（占 1.8%），
   集中在 8~50 kW 的近停机降载工况。
   → 优化程序接入前必须做非负钳制：P = max(P, 0)。

2. 不可外推
   随机划分的测试误差不等于外推到全新风况的误差。

3. 标签源是解析模型，不是真实流场
   数据由 FLORIS 解析尾流模型生成（单机气动已按 NREL 官方功率曲线标定，
   偏差 ≤1.3%），但尾流叠加部分尚无 CFD 或实测对标。
   因此本模型是「FLORIS 的代理」，不是「物理真值」。
   优化给出的最终方案仍应经 FLORIS 复核；有条件时用 Fluent 算例交叉验证。

十、三个模型分别对应哪版数据
----------------------------------------------------------------
包里一共有三个训好的模型，架构完全相同（冻结主干 + 27,106 个可训练参数），
差别只在训练用的数据版本：

路径                              数据版本    行数     轮次   功率 MAE   坐标口径
model\trained.keras               v3        20,160   200    50.9 kW   scaled
model\versions\v1\trained.keras  v1        15,264   177    30.1 kW   scaled
model\versions\v2\trained.keras  v2        13,440   187    25.4 kW   scaled

怎么选：
  1. 用于优化、需要逐机桨距与转速  -> 用 v3。它是唯一"桨距效应真正学到了"的版本
     （桨距响应偏差 1.15%）；v2 在这一项上是 84.0%，属于失效。
  2. 要对照"统一控制 vs 逐机控制"的影响  -> 三个都加载对比。
  3. 需要更细的风速分辨率（0.5 m/s 步长）  -> v1 在纯风况统计上仍有参考价值。

使用注意：
  1. 三个模型各配一份 config_used.json（机位、单位、口径），加载时用各自目录里的那份，
     不要混用。
  2. 不要跨数据评测：用 v3 的数据去评 v1/v2 的模型，或反之，结论都不公平
     （v3 新增了 8 kW 量级的深度降载工况，任务难度不同）。
  3. 三个模型都存在负输出问题，v3 最严重（1.8%），下游使用前必须做 P = max(P, 0)。
