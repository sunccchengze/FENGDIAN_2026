## 3. 核查结论（2026-10-25，孙承泽侧独立复核）

完整判定见 [`EVID-2026-004`](../../../docs/evidence/EVID-2026-004_仿真建模数据交接核查.md)。要点：

- **"实测数据"这个说法不成立。** 包内没有任何实测/外场/SCADA/CFD 标签数据；`label_source = simulation`，
  `status = trained_requires_independent_physical_validation`。数据来自 FLORIS 解析模型。
- **数据本身自洽，可被独立复算。** 我用 `P = 0.5ρA·Ueff³·Cp·η·cos^1.88γ` 反推隐含 `Cp·η`：上限 0.4566（= 0.4836 × 0.944），
  无越界、无负功率；作者自述"由 (Ueff, λ, β, γ) 独立复算功率，中位偏差 0.000%"可复现。
- **响应校验是真证据。** 桨距 1.15%、偏航 2.14%、风向 1.98%、风速 8.26%；且 v2 的 25.4 kW 低误差掩盖了
  84% 的桨距响应失效——这是"留出误差正常 ≠ 学到控制响应"的现成案例。
- **已知缺口与作者自述一致**：尾流叠加无 CFD/实测对标；无 PDE 残差项；准静态；445 个负输出（1.8%，下游必须 `max(P,0)`）；
  风速 5–12 m/s、`|γ| ≤ 20°`、桨距 0–14° 之外属外推。

## 4. 包内两处口径不一致（已记录，未改作者文件）

1. `training_report.json` 写 `Ueff` 取样为 "4 radii × 8 azimuths = 32 points"，而 `docs/dataset_manifest.json`
   与 `README.txt` 都写 8 半径 × 16 方位 = 128 点。以 128 点为准，training_report 该行是旧值。
2. `model/config_used.json` 的说明文字里有"**实测**该口径误差最低（30.1 kW…）"，此处"实测"指"实际测试过"，
   与"实测数据"同形不同义；对外引用时不要照抄这句话。
