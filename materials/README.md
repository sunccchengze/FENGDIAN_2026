## 2. 归档规则

1. **按内容主责分类，不按上传人分类。** 孙承泽上传过洪祖名的 PPO 交付，它在 `洪祖名/`；袁夫达发的 zip 里有厉今飞训练的网络，网络部分解压到 `厉今飞/`，数据部分解压到 `袁夫达/`。
2. **自己制作或负责解释的源文件、报告、交付件放自己目录；多人共同形成或对外提交的版本放 `集体/`。** 同一份文件不放两处。
3. **平台代码、数据管道与实验事实不搬进 `materials/`。** `viz/`、`twin/` 的代码与数据留在原处，材料只引用它们（`viz/` 里剩下的都是平台运行 / 复现所需，见 `孙承泽/README.md` 末节）。
4. **原文件名一律不改**，只加子目录；仅三处例外（均经用户 2026-09-21 确认）：`20260808/README.md` → `集体/20260808_群聊纪要_…md`，`假期前PPT.md` → `集体/假期前PPT_大创项目假期技术路线.md`，去掉全部 6 个文件名里的浏览器下载后缀 `(1)`（申请书、建模与数据生成、田铭雨仿真记录、9.19 会议方案、`20260810洪/` 的 zip 与 md）。
5. **交付包只保留解压件**（用户 2026-09-21 决定）：zip 逐文件核对 sha256 一致后删除，zip 本体的 sha256 与取回提交记在对应 README 与 `viz/_archive/MANIFEST.md`。例外：`洪祖名/20260810洪/` 的 zip 保留，因为它与旁边的 `extracted/` **不是同一内容**（zip 内 `.pt` 为 0 字节、`simplified_turbine_env.py` 为 1180 B 原版，`extracted/` 是可视化侧 2026-08-10 复现后的版本）。
6. **每个数字都要能回到证据。** 材料 Issue 写清用途、截止时间、主责人、审阅人、代码 / 数据版本和真实 / 代理 / 演示 / 示意标签。
7. **不要使用 `final_v2`、`latest_new` 等含糊命名。** 用日期、用途和 Git 提交记录区分版本。
8. **聊天截图先转录再入库。** 截图按「日期_类型_内容」命名放 `集体/聊天记录/`，同目录 Markdown 逐条照录中文原文（不录微信机翻），并注明每份文件现在的归档位置；文件归属以截图里的发送人为准。
9. **Office / PDF 一律带 Markdown 镜像。** 新增 docx / pptx / pdf 后运行 `python3 tools/markitdown_sync.py`；不要手改镜像，不要把镜像当源文件引用。
10. **解压入库的交付件带 `SHA256SUMS.txt`。** 删除原 zip 只保留解压件时，在解压目录生成逐文件 sha256 清单（`sha256sum * > SHA256SUMS.txt` 或见 4 份现有清单的格式），不含自动生成的镜像；`python3 ci/repo_quality.py` 会逐文件校验，任何改动都要同步更新清单并在 README 说明原因。

## 3. 文件分层

| 类型 | 含义 | 规则 |
|---|---|---|
| 源文件 | Markdown、脚本、可编辑文档或演示源 | 允许通过 PR 修改，是可追溯的编辑入口 |
| 生成文件 | PDF、PPTX、DOCX、图片或网页导出 | 标注生成时间、源文件、代码 / 数据版本 |
| 提交快照 | 已提交给老师、评审或答辩的冻结版本 | 不再覆盖，写明日期、对象和提交内容 |
| 交付快照 | 队友交给集成方的 zip / 权重 / 结果 | 原包不改，解压件旁注作者与复现状态 |

## 6. 材料工作流

1. 先创建材料 Issue，写清受众、时长、截止日和提交格式；
2. 使用 [`docs/templates/材料记录模板.md`](../docs/templates/材料记录模板.md) 登记源文件和生成文件；
3. 每个关键数字填写证据卡编号和适用范围；
4. 由至少两名成员审阅，其中一名必须是相关领域主责人；
5. 生成 PDF/PPTX/DOCX 后登记生成工具、日期、commit 和数据版本；
6. 提交后冻结快照，不用覆盖式「最终版」命名；
7. 将提交版本、反馈和后续修改记录到 Issue 或会议纪要。
